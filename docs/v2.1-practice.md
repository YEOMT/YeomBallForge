# v2.1 로컬 반복 육성 검증

공개 정적 클라이언트의 **혼자 연습하기 → 반복 육성 · 3슬롯 연습**은 실제 온라인 학생이 없는 비경쟁 CPU 연습이다. 서버에 결과·Elo·보상을 제출하지 않는다. 연습 문항의 정답 키는 이 로컬 모드에만 포함하며, 교실 문제은행의 비공개 정답과 섞지 않는다.

## 실제 구현

- 15분 기본 반복 육성, 최초 10장 한 번 지급, 유효 정답마다 2장 즉시 지급. 같은 시도 재전송은 재지급하지 않고 같은 문항 재보상은 90초와 다른 문항 min(4, 은행 수−1)개 응답을 함께 요구한다.
- 공 3슬롯과 공유 지갑. 무료 생성·삭제·초기화로 재화를 지급하거나 히든 원장을 재설정하지 않는다. 보관 잠금과 출전 잠금은 분리한다.
- 온라인과 동일한 shared forge의 확률/보호 1·2·3개/무보호 초기화/경로/폼/특성을 사용한다. 성공/실패 결과를 먼저 보이고 300ms 뒤 확인하면 필요한 선택이 나타난다. 단회 퀴즈·토너먼트·럼블도 이 강화 흐름을 쓴다.
- CPU 경기 중에도 다른 공과 퀴즈를 사용할 수 있다. 출전 공은 독립 스냅샷이고 경기 종료 알림은 현재 퀴즈 DOM을 교체하지 않는다. 새 경기에는 같은 sim의 체력·쿨다운·전투 자원 초기화가 적용된다.
- 최대 40초의 CPU 1:1을 실제 공유 sim으로 판정한다. 최근 3경기의 실제 상태/사건을 저장하여 다시 보여 주며, 별도 비교 연습은 보관 공 사본과 지난 상대 스냅샷만 사용한다. 재생·승리·패배로 강화권을 지급하지 않는다.
- 15분 후 신규 강화·보상·출전을 닫고 45초 정리 후 합법적 기본 선택으로 마감한다. 정리 시간 내 끝나지 않은 CPU 경기는 무효 처리한다. 이 로컬 수업은 서버 방 복구나 영구 계정 저장 기능이 아니다.

## 실행한 검사

`node --test tests/forge.test.js tests/forge-v21.test.js tests/forge-practice.test.js`: **22 PASS**. 금액·확률·경계·특성·슬롯·수업 팩·정확 DP 및 로컬 반복 문항/결과 확인/출전 스냅샷을 검사했다.

`node tools/practice-v21-browser.mjs`: **5묶음 PASS**, pageerror 0. 환경은 Windows Node 24 + Playwright 1.51.1 Chromium, 1440×900와 390×844 viewport다. `PLAYWRIGHT_MODULE`은 기존 Playwright의 `index.mjs`, `PLAYWRIGHT_BROWSERS_PATH`는 설치된 브라우저 경로로 지정했다. 스크립트가 임의 로컬 포트의 서버를 열고 끝나면 브라우저와 서버를 모두 닫는다.

1. 실제 클릭으로 정답 2장 즉시 지급 및 무료 세 슬롯 생성.
2. 지정된 로컬 강화 난수에서 실제 UI 10회 강화 → 매번 결과 먼저 표시 → 경로/공/특성 선택. 결과 전 후보 버튼은 0개다.
3. 실제 시간 동안 CPU 경기 진행 → 퀴즈로 이동 → 경기 종료 후 동일 퀴즈 DOM 노드와 문항 유지. 경기 종료 보상 0, 다음 정답 보상 2장.
4. 보존된 CPU 기록 재생, 비교 연습의 특성 변경 후 실제 보관 특성과 지갑 불변.
5. 390px 휴대폰 화면의 강화 조작 폭과 인벤토리. 화면은 내부 스크롤을 사용한다.

실행 원본은 `artifacts/v2.1-practice/`에 남기고 PR에서 검토할 증거를 별도로 보존했다: [결과 JSON](evidence-v2.1-practice/results.json), [T10·특성 선택](evidence-v2.1-practice/three-slot-t10.png), [CPU 경기](evidence-v2.1-practice/cpu-battle.png), [기록 재생](evidence-v2.1-practice/cpu-recorded-replay.png), [390px 강화 화면](evidence-v2.1-practice/mobile-390x844.png), [390px 인벤토리](evidence-v2.1-practice/mobile-inventory.png). 캡처를 직접 열어 확인했으며, 코드 수정 뒤 최종 브라우저 검사도 다시 통과했다.

강화 UI 검사에는 고정된 로컬 난수를 사용했다. 학생 플레이 도달률이나 실제 스마트폰 FPS 측정으로 해석하지 않는다. 실기기 터치/청취 및 Safari/Firefox는 **NOT RUN**이다. 전체 앱 빌드·실시간 학생 연결·부하 검증은 별도 최종 보고서를 따른다.
