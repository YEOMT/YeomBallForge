# 교실 세션과 WebSocket 검증

Windows와 Node.js 24.22.3에서 로컬 서버를 열고 측정했다. 교사와 학생은 각각 독립 WebSocket으로 접속했다. 부하 검사에서는 서버와 테스트 클라이언트가 한 프로세스를 공유한다.

## 재현

```sh
npm ci
node --test tests/forge.test.js tests/session.test.js
node --expose-gc tools/socket-load.js
```

## 부하와 전송량

검사 도구는 30명의 퀴즈 답안을 제출하고 실제 강화 명령으로 공을 만든다. 토너먼트, 럼블, 복합 모드, 럼블 순서로 같은 방에서 네 번 경기했다. 각 측정 구간은 실제 시계로 진행한다. 구간이 끝나면 검사 도구에서 서버 시계만 앞당겨 같은 60Hz 시뮬레이션으로 결승·결과·재경기를 검증한다. 전송량은 WebSocket 압축 협상 후 TCP 소켓에서 수신한 바이트를 기준으로 한다.

| 실시간 측정 구간 | 4개 동시 결투 | 30인 럼블 |
| --- | ---: | ---: |
| 접속 수 | 31 | 31 |
| 측정 시간 | 4.44초 | 4.45초 |
| 서버 전투 tick 처리 묶음 p95 / p99 / 최대 | 0.46 / 0.79 / 0.87 ms | 0.55 / 0.64 / 1.78 ms |
| 관전 선택 명령 왕복시간 p95 | 8.21 ms | 16.88 ms |
| 교사 수신 스냅샷 | 10.14회/초 | 9.88회/초 |
| 교사 수신량 | 20.78 KiB/초 | 36.80 KiB/초 |
| 학생 1명당 평균 수신량 | 14.91 KiB/초 | 37.11 KiB/초 |

전투 중 학생의 접속 종료부터 재인증과 첫 현재 경기 화면 수신까지 15.06 ms가 걸렸다. 네 번의 재경기 초기화 직후 강제 GC 후 힙은 각각 11.97, 11.14, 10.65, 11.13 MiB였다. 매번 30명의 참가자, 빈 명령 기록, 초기화된 재화, 해제된 전투 참조를 확인했다. 서버 전투 tick 수치는 고정 시간 간격 하나 이상을 처리한 runner 호출의 시간이며 소켓 직렬화·전송 시간을 포함하지 않는다.

실제 학교 무선망, 학교 기기의 렌더링 프레임률, 장시간 다중 방 운영 성능은 별도 현장 측정이 필요하다.
