## 렌더 비용과 20% 초과 관측

별도의 quiet 구간에서 기준/신규를 순차 실행했습니다. 같은 합법 T5 30공, 시드 210126, 장면당 6.5초, 첫 20개 표시 프레임 제외, 소리 꺼짐 조건입니다. 측정치는 Canvas 프레임 함수의 wall-clock CPU 시간이며 서버 성능이나 실물 휴대전화 FPS가 아닙니다. 시각 회귀 중 동시 분석 작업이 있었던 실행은 성능 수치로 사용하지 않습니다.

최초 측정에서 저사양 P95가 3.5→5.3ms(+51.4%)여서, 저사양(DPR 1) 피해/방어/회복 숫자만 최대 96개의 text sprite로 캐싱했습니다. 값·폰트·색상·위치·투명도와 실제 판정은 유지했습니다. 두 원자료를 모두 보존했습니다.

## 물리 계측과 실제 연결

[40개 준비 fixture](evidence-v2.2/impact-comparison.json)는 같은 합법 T5/T19·위치·기본 속도로 비교했다. v2.2 진화 조건을 추가 배치한 경우를 별도로 표시한다. 일반 벽 충전 철퇴는 양 버전 모두 충격량 268.75다. 진화까지 준비하면 327.875, 350ms 경로는 43.13→48.97, 실제 벽꿍 피해는 5.6→6.4가 된다. 해일 진화 반격은 92→115, 350ms 경로 21.12→26.40이다. 빔 회피 fixture는 양쪽 모두 피해 0이며, 이것을 화면 효과만으로 유효타처럼 만들지 않는다.

첫 장시간 시도는 큰 리플레이 전송 후 `ackForge` timeout으로 **FAIL**했다. 당시 최대 응답은 1,133,677바이트였다. `ws.bufferedAmount`에 압축 대기 중인 정상 리플레이의 원문이 포함되어 기존 1MiB 느린 연결 차단과 충돌했다. 기존 동작의 1013 종료를 재현한 뒤 다음과 같이 수정했다.

- 리플레이 1건만 기록 상한 2MiB + 명시적 envelope 여유 128KiB로 분리 추적한다. 병렬 요청은 archive 압축 해제 전에 거절한다.
- 일반 프레임 256KiB 생략과 일반 대기 출력 1MiB 차단은 유지하며, 일반 출력의 예약량을 별도로 세어 리플레이 여유를 빌리지 못한다.
- 15초 전송 대기 시 연결 종료를 시작하고, send callback·오류·close에서 추적과 타이머를 해제한다. 추적 WeakMap에 payload 복사본을 저장하지 않는다.
- 실제 permessage-deflate 소켓으로 1,452,171바이트 기록, 뒤따른 강화 확인 ACK, 동시 리플레이 거절 및 완료 후 재요청을 검증했다. 신규 7개 전송 회귀와 기존 권한·세션 회귀가 전체 260개에 포함된다.

브라우저 최초 시도 중 localhost sandbox 차단은 **INFRA_FAILURE**, 중복 버튼을 찾은 테스트 선택자는 **FAIL (테스트 선택자)**로 구분했다. 허용된 로컬 실행 권한 및 실제 탭 범위 선택자로 다시 실행한 최종 37개 그룹은 모두 PASS다. 게임 오류를 숨기기 위해 assertion을 제거하거나 timeout을 늘리지 않았다.

## 실제 15분 연속 검사

[기준 원자료](evidence-v2.2/soak-before.json)와 [수정 후 원자료](evidence-v2.2/soak-after.json). 최종 실행은 **901,000.3ms** 동안 교사 1+학생 30의 실제 loopback WebSocket으로 409경기, 최대 15동시 경기, 22,764개 명령을 처리했다. 합법 고급 빌드는 테스트가 배치했고 다른 슬롯은 실제 퀴즈·강화·결과 확인·선택을 진행했다. 자연 교실 플레이의 도달 확률을 나타내지 않는다.

재접속 14회, 리플레이 조회 37회, 실제 2초 일시정지, 수업 종료·진행 경기 정리 및 같은 방 재경기까지 PASS다. 재경기 지갑 10장·Elo 1000 초기화를 확인했다. 학생 프레임/사적 정보 누출 0, 예상하지 않은 연결 종료 0, 오류 0. 기록된 1006 종료는 계획한 재접속 및 마지막 테스트 정리의 `expected:true` 종료다. 서버·공통 시뮬레이터·manifest의 원문 SHA-256을 시작/종료에 비교해 실행 중 변경이 없음을 확인했다. [검증 소스 지문](evidence-v2.2/source-fingerprint.json)은 로컬 원문 바이트 기준이며 Git 정규화 후의 다른 OS 줄바꿈과 혼동하지 않는다.

GC에 따른 하락과 보관 기록 상한을 관찰했으나, 15분보다 긴 기간의 누수 부재를 보장하지 않는다. 변경본 관측 ACK P95 203.64ms, tick batch P95 2.61ms, 최대 42.79ms, event-loop P95 40.57ms, 한 코어 환산 CPU 52.48%다. 두 장시간 실행 중 다른 개발 검증이 있었으므로 이 CPU·지연 수치를 직접 개선율로 비교하지 않는다. ## 최종 독립 소켓 성능 비교

장시간 실행과 다른 무거운 작업이 끝난 뒤 기준→최종을 순차 실행했다. 같은 합법 빌드, 경기별 고정 seed `210126 + index`, 31소켓·15동시 경기, 각 720개 명령을 포함하는 6.15/6.52초 정상 시간 구간이다. 종료 후 가속 정산/리플레이/럼블은 이 CPU·지연 측정에서 제외했다. 원자료: [기준](evidence-v2.2/baseline-server-load.json), [최종](evidence-v2.2/final-server-load.json).

| 지표 | v2.1 | 최종 v2.2 | 변화 |

| tick batch 최대 | 3.93ms | 6.27ms | +59.5% |
| ACK P50 / P95 | 39.98 / 119.54ms | 54.04 / 142.33ms | P95 +19.1% |

tick P95는 4ms 후보 기준 이내지만 상대 증가율 목표에는 미달이다. 진화·각성 상태 전이/형상, 별도 공개 자원, 실제 사건 정보와 전송량 추적이 추가됐다. 기록 프레임 크기와 표본 경기 사건 수(325→407)의 증가는 원자료로 확인된다. 이동 진화 사건의 10% 경계 양자화, 비활성 상태 조기 반환, 객체/사건 상한 및 전송 제어를 적용했어도 비용이 남는다. **각 함수의 CPU 기여를 분리한 프로파일링은 NOT RUN**이며, 전부 특정 한 함수 때문이라고 단정하지 않는다. 짧은 실행 간 편차도 있어 장시간 용량 보장으로 사용하지 않는다.

같은 도구의 가속 럼블 행은 seed/종료 시간까지 통제한 전후 성능 표본이 아니므로 위 비교에 포함하지 않는다. 별도 고정 seed의 최종 30공 스트레스는 자연 15회·재실행 16회·준비 각성 1회 모두 PASS다. 최대 투사체 90/전역 한도120, 필드30/30, 이벤트128/128; 준비된 30개 각성이 같은 18틱에 발동하고 30개 소유자의 투사체90개를 확인했다. 학생 전체 좌표 비공개도 실제 소켓 검사에서 유지했다.
