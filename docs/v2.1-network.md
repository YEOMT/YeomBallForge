# v2.1 서버 계약과 실제 검사

2026-11-26 · 기존 `d6967bc`의 Node ES modules / WebSocket / 공통 시뮬레이터를 확장했다. 운영 AWS·DNS·컨테이너·Pages 설정은 변경하지 않았다.

## 수업과 권위

- 기본 모드는 `ranking`, 시간은 15분(교사 설정 5~30분)이다. `LOBBY → ACTIVE → DRAINING → RESULTS`와 교사 일시정지가 학생의 화면 탭과 분리된다. ACTIVE의 새 참가자도 즉시 시작하며, 다른 모드의 늦은 참가자는 기존대로 다음 판을 기다린다.
- 학생별 공 3슬롯은 하나의 강화권/유지권 지갑을 사용한다. 세션 기본 10장은 한 번, 정답은 즉시 2장이다. 초기화·새 공·재접속·승패·리플레이·개인 목표는 재화를 지급하지 않는다.
- 문제는 아직 응답하지 않은 문항부터 출제한다. 재출제는 응답 후 논리시간 90초와 서로 다른 다른 문항 `min(4, 은행 수-1)`개를 모두 만족해야 한다. `attemptId`의 현재 문항 첫 답안만 채점한다. 작은 은행의 `quizWaitMs`를 제공하며 설명과 실제 정답은 응답한 학생에게만 보낸다.
- 서버의 runId, connectionEpoch, commandId가 오래된 판·연결과 중복 명령을 구분한다. 승인된 명령 응답을 복사해 보존하므로 이후 선택이나 단계 변경도 원래 응답을 바꾸지 않는다. 같은 commandId 재전송은 강화 RNG나 지급을 다시 실행하지 않는다. 세션당 학생의 승인 명령 원장은 8,192개로 제한한다.
- 공 변경은 복사된 슬롯과 공통 지갑에서 동기적으로 검증한 뒤 한 번 커밋한다. 부족한 보호 비용은 RNG/차감 전에 거절한다. 대기·경기의 공은 잠기지만 다른 슬롯과 퀴즈는 사용 가능하다. 보관 잠금은 출전을 허용하고, 변경은 명시적 해제 이후만 허용한다.

## 강화 결과 순서

`enhance` 응답과 슬롯의 `lastForge`에는 commandId/resultId, 판정 수치, before/after, 지갑 결과, 불변 후보 원장, createdAt, acknowledged를 보존한다. 결과를 받은 화면은 문구를 먼저 보여 주고 `ackForge`를 보낸다. 서버도 300ms 전 결과 확인과 미확인 상태의 다음 강화/선택을 거절한다. 경로/폼/히든/필요한 특성 선택은 같은 resultId에 연결된다. 현재 합법성은 공통 콘텐츠 규칙으로 재검증한다.

선택한 슬롯은 `me.pendingForge`, 모든 슬롯은 `me.inventory.slots[n].lastForge`로 재접속 시 복원된다. 호환 특성은 새 폼에서도 유지하고, 필수 선택이 남으면 READY/대기열 참가를 막는다. 매 경기마다 특성을 다시 선택하지 않는다.

## 매칭, 관전, 정산

- 가장 오래 기다린 학생을 먼저 뽑고 후보의 레이팅/티어 차이를 완만한 가중치로 사용한다. 다른 후보가 있으면 직전 상대를 피하고, 15초 대기 후 체급/레이팅 가중치를 완화한다. 같은 티어만 허용하는 리그나 숨은 봇은 없다.
- 매칭 순간 양쪽 출전 빌드·레이팅·시드·규칙 버전을 고정한다. 취소가 먼저 확정되면 취소하고, 매칭이 먼저 확정되면 취소를 거절한다. 학생 하나가 동시에 두 경기에 들어갈 수 없다.
- 서버가 최대 15개의 1:1을 판정한다. 최대 40초, 30초부터 압박한다. 랭킹의 완전 동률/동시 KO는 무승부이고, 토너먼트의 진출자 판정과 구분한다. Elo는 시작 1000, K=32, 동률 레이팅 승패 ±16이다. 양쪽 점수는 matchId당 한 번 커밋한다. 클라이언트가 신고한 승패·피해는 받지 않는다.
- Top10은 공통으로 제공하고 내 순위·점수·최근 변화는 10위 밖에서도 제공한다. 다른 학생의 지갑, 현재 문제, 응답 원장, 복구 토큰은 전송하지 않는다.
- 학생의 경기 프레임에는 자기 경기 하나만, 교사는 선택 경기 하나만 포함한다. 전체 15경기의 이벤트를 학생마다 복제하지 않는다. 럼블 학생은 본인 정보·처치자·순위만 받는다.
- 호스트 송출은 새 경기가 생겨도 자동 전환하지 않는다. 랭킹에서는 선택 경기의 결과를, 기존 토너먼트에서는 완료된 선택 전장 한 개의 마지막 프레임을 유지하고 다음 후보 선택을 기다린다.

## 종료와 복구

교사 일시정지는 방 논리시간, 경기 tick, 반복 문항 대기와 매칭 대기를 함께 멈춘다. 진행 중 학생 연결이 끊겨도 경기는 계속 정산한다. 대기열에서 끊긴 학생은 대기를 취소하며 같은 토큰으로 복귀할 수 있다.

DRAINING은 신규 정답 보상·강화·대기/매칭을 차단한다. 이미 승인된 resultId의 확인·경로/폼/히든/특성 선택만 허용한다. 진행 경기가 끝나고 선택도 끝나면 결과로 이동하며, 논리시간 45초가 지나면 합법적 기본 선택을 확정하고 미응답 히든은 거절한다. 남은 비정상 경기는 무효, 점수 변화 0으로 정리한다. 자동 선택은 `me.autoFinalized`에 표시할 자료로 남긴다.

**복구는 같은 서버 프로세스의 브라우저 재접속이다. 서버 재시작을 넘는 영구 방 복구는 지원하지 않는다.** 방은 12시간 또는 모든 연결이 끊긴 뒤 15분에 만료된다. 새 판에서는 지갑·전투력·레이팅·발견/목표와 경기 기록을 새로 시작한다.

## 리플레이와 보존 한도

- 정식 경기마다 초기 스냅샷, 실제 RNG 시드, 규칙/콘텐츠/경제 버전, 서버의 6 tick 간격 상태, 모든 새 사건, 최종 해시와 사건 기반 요약을 저장한다. 기본 재생은 이 원본 상태와 사건을 이용하며 새 규칙으로 다시 시뮬레이션한 결과를 원본으로 바꾸지 않는다.
- 완료된 경기 자료는 deflate로 한 번만 보관한다. 학생의 최근 목록은 matchId 3개만 참조한다. 최대 30학생의 최근 참조 90개와 교사 선택 결과 한 개 외의 기록은 제거한다. 새 판/방 종료에서 해제하며 영구 아카이브를 만들지 않는다.
- 경기 기록은 2MiB 원자료 예산(메타데이터 예약 포함), 2,400 tick, 40,000 사건 상한을 갖는다. 압축 아카이브는 64MiB 예산으로 새 매칭 전에 진행 경기별 예약 공간도 계산한다. 용량이 차면 기존 최근 3경기를 지우는 대신 대기 상태와 이유를 제공한다. 비정상 기록 상한 초과는 무효로 처리하고 `unavailableReason`을 명시한다. 이를 정상 원본 재생이라고 표시하지 않는다.
- `replay`는 참가 학생의 현재 세션 최근 3경기 또는 교사만 요청할 수 있다. 읽기 응답은 명령 원장에 중복 저장하지 않으며 연결별 10초에 8회로 제한한다. 조회·재생에는 재화/Elo/목표 지급 경로가 없다.
- 전투 요약은 공통 `summarizeEvents()`의 실제 피해/방어/기술과 원인 eventId를 사용한다. 원본과 비교 연습은 별도 실행이다.

## 수업 팩과 개인 목표

`packages/content/packs.js`는 전체(`all`), 입문(`intro`: 화염·물결·대지), 방어와 반격(`defense`: 물결·대지)을 제공한다. 모든 팩은 T18~T11에 2개 이상, 각 T10~T1의 활성 경로별 3개 이상과 공용 6개를 검증한다. 설정은 로비에서만 변경하고 모든 학생/새 슬롯에 같은 팩을 적용한다. 초기화에도 팩과 히든 원장은 유지된다.

개인 목표는 서로 다른 2프로필 출전, 유효 방어 후 실제 반격 적중, 시작 점수보다 높은 개인 최고점의 3개다. 완료한 정식 경기에서만 기록하고 중복 정산/리플레이/무효 경기에서는 갱신하지 않는다. 실제 발견한 프로필도 세션 안에서 기록한다. 추가 재화나 영구 능력치는 없다.
