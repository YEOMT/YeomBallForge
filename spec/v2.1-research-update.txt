YeomBallForge v2.1 — 강화 희소성 · 전투 선택 · 재도전 경험
다른 볼파이트 조사 + 확률 검토 + Codex 구현 명세
작성 기준: 2026-11-25 / 설계 문서 버전 2.1 / 아직 운영 반영되지 않은 제안
======================================================================

문서 사용법
----------------------------------------------------------------------
이 문서는 기존 v2 업데이트 명세를 이어받는 설계 개정판이다.
이번 대화에서 수행한 작업은 조사·소스 확인·확률 계산·명세 작성이다.
이 문서를 작성하면서 게임 코드 수정, 원격 push, 병합, 운영 배포를 수행하지 않았다.

Codex에 구현을 맡길 때는 이 문서와 기존 YeomBallForge_v2_Codex_Update_Spec.txt를 함께 제공한다.
아래 1절의 변경 목록이 기존 v2 문서와 충돌하면 이번 문서가 우선한다.
기존 v2 문서를 구할 수 없어도 3절의 필수 기반과 각 절의 완료 조건으로 구현 범위를 확인할 수 있다.
현재 브랜치에 이미 구현된 기능은 실제 코드와 테스트로 확인하고 재사용한다.
문서에 적힌 과거 커밋으로 코드를 강제로 되돌리지 않는다.

핵심 설계 판단
----------------------------------------------------------------------
1. 모든 강화 단계에 실패 가능성을 둔다. 최종 T1 단일 성공률은 3%를 권장한다.
2. 최종 희소성은 성공률, 정답당 재화, 유지권 비용, 수업 시간을 함께 평가한다.
3. T10~T5에서 이미 공의 개성이 완성되어야 한다. T3는 강한 실전 목표, T1은 드문 특별 목표다.
4. 새 선택 시스템은 공당 전술 특성 1칸부터 시작한다. 별도 가챠·장비 화폐를 동시에 늘리지 않는다.
5. 타격의 원인, 강도, 결과가 화면에서 이어져야 한다. 공마다 다른 리듬과 대응법을 만든다.
6. 패배 후 최근 경기를 이해하고, 다른 특성이나 보관 공으로 바로 다시 도전할 수 있게 한다.
7. 신규 공 수 확대와 기존 공 완성도를 분리해서 보고한다. 외형 개수와 전투 프로필 개수를 혼동하지 않는다.

1. 현재 확인 상태와 이번 문서의 우선 변경
======================================================================

작업 대상
- 저장소: https://github.com/YEOMT/YeomBallForge
- 공개 프런트엔드: https://yeomt.github.io/YeomBallForge/
- 로컬 조사 기준 main 커밋: d6967bc22e8710bb296c47ee65916cbd4fa3ad6d
- 원격 main의 package.json과 경제 파일을 다시 확인한 결과: 버전 1.1.0의 기존 규칙.
- 조사한 로컬 작업 트리는 깨끗했다. 다른 작업 브랜치나 외부 Codex 작업의 완료까지 확인한 것은 아니다.

현재 코드에서 확인한 사실 [S1]
- 목표 T19~T11 강화는 100%, T10 85%, 최종 T1 10%다.
- 실패 시 현재 T9~T2에서 한 단계만 내려가며 T10 바닥이 있다. T20 초기화가 구현된 상태가 아니다.
- 10장 기본 지급, 정답당 2장, 유지권 가격 2장은 이미 정의되어 있다.
- 랭킹 도전·3슬롯·상시 퀴즈는 기존 v2 설계의 목표이며 현재 main에서 구현 완료라고 보지 않는다.
- 현재 268개 티어별 폼 정의와 26개 전투 프로필이 있다. 서로 다른 기믹 268개라는 의미가 아니다.
- Node ES modules, 공통 JavaScript 시뮬레이터, Canvas2D, WebSocket 구조다.

기존 v2 제안에서 이번에 바꾸는 것

항목 | 기존 v2 제안 | 이번 권장안

결과 경험 | 재도전 버튼과 기본 결과 | 실제 판정 요약, 최근 3경기, 비교 연습

이전 문서의 '첫 두 승급 100%' 완료 조건과 이전 확률 분석 표는 이번 표로 대체한다.
이전 확률표와 새 유지권 규칙을 섞어 구현하지 않는다.

2. 다른 게임 조사: 확인한 기능과 적용 판단
======================================================================

조사 방법
- 개발자 공식 페이지, 공식 스토어 설명, 개발 로그, 공개 소스를 사용했다.
- 직접 설치 플레이, 실제 스마트폰 FPS 측정, 음향 체감 비교는 수행하지 않았다.
- 아래 기능 존재는 출처에 근거한다. YeomBallForge에 적합한지는 별도의 설계 판단이다.
- 신규·소규모 제품의 기능을 흥행으로 검증된 공식처럼 다루지 않는다.
- 참고 게임의 싱글플레이 보상 구조를 30명 교실 PvP에 그대로 옮기지 않는다.

2.1 Random.GG BALL//FIGHT [S2]
확인: 캐릭터 대전, 기본/각성 형태 탭, 캐릭터·작품 검색, 승패·레이팅, 배속·큰 화면·음악/효과음 제어.
적용: 다음 형태 미리보기, 능력 유형 검색, 공의 정체성이 보이는 선택 카드, 리플레이 배속.
경계: 각성 탭이 전투 중 각성 발동을 뜻한다고 단정하지 않는다. 베팅·관전 시간 채우기 보상을 가져오지 않는다.

2.2 Weapon Ball Fight / BalanGo [S3]
확인: 여러 무기의 자동 물리 전투. 확인한 공식 12.5 업데이트는 커스텀 공 에디터, 샌드박스 시간 제어, GIF 스프라이트, 중복 입력·큰 저장 데이터 개선을 설명한다.
적용: 실험실, 느리게 보기, 외형과 판정 분리, 모바일 중복 클릭·재접속 안정성.
경계: 공개 경쟁 모드에 학생이 임의 행동 스크립트를 실행하는 기능은 이번 범위에서 제외한다.

2.3 Ball Game / Blue Coyote Studio [S4~S7]
확인: 무기 공에 파워 카드와 반복 성장 선택을 결합한 게임. 이 설명은 itch 배포 페이지와 해당 게임 개발 로그를 기준으로 한다.
v1.6 로그: 실제로 소환 가능한 빌드에 소환 관련 카드를 제시, 수치 툴팁, 패링 시각 효과, 반사 재귀·NaN·경기장 이탈 수정, 선택 상태 이어하기.
v1.3 로그: 시작 카드 때문에 재시작을 반복하는 문제 개선, 저사양 모드, 도감·설명·터치 조작 개선, 결과 시드 표시.
v1.1 로그: 배속, 시드 지정 재현, 시드 지정 실행의 진행 보상 분리.
적용: 무효 특성 제외, 실제 계산과 같은 설명, 첫 선택의 통제권, 재현 가능한 연습과 랭킹 보상 분리.
경계: 수백 개 카드·대량 투사체·무한 중첩을 한 번에 도입하지 않는다.

2.4 Gladiorb: Weapon Ball Arena / Bumblebolt [S8]
확인: 무기 공 전투, 승리 후 세 후보 중 업그레이드 하나 선택, 중첩 능력, 보스, 마지막 일격 슬로모션, 사운드·음악·진동 제어. 수동 대시도 존재하므로 완전 자동만 있는 게임이라고 부르지 않는다.
적용: 세 가지 전술 선택, 짧은 KO 하이라이트, 충돌·벽·가드·KO 음향 분리.
경계: PvP 승자에게만 계속 영구 능력을 더하지 않는다. 수동 대시와 출석 보상은 도입하지 않는다.

2.5 BALLRENA / vampireblackcat [S9~S10]
확인: CORE 선택, 격자 부품 구성, 합성 후 선택, 전투와 재구성. 공식 공지는 위험과 보상을 함께 가진 코어, 정확한 충전/누적 수치, 보호막 피격·파괴, 반동·실제 발사 위치 정렬 등을 설명한다.
적용: 본체 기믹+특성 하나, 실제 장단점, 방어·차지·반격의 작동 표시.
경계: 5×5 가방, 부품 상점, 추가 화폐까지 수업 루프에 동시에 넣지 않는다.

2.6 Super Auto Pets [S11]
확인: 자동 전투 능력 조합, Arena/Versus 구분, 공통·커스텀·주기적 팩.
적용: 교사가 고르는 수업별 공 구성, 같은 방에서는 같은 후보 풀, 명확히 표시된 비랭킹 연습.
경계: 패배 누적으로 수업에서 영구 탈락시키지 않는다.

2.7 Backpack Battles [S12]
확인: 아이템 선택·배치·조합으로 자동 대전을 준비하며, 상대 구성과의 대응이 중요하게 다뤄진다.
적용: 티어 외의 작은 전술 선택, 상대 기믹을 보고 보관 공을 교체하는 이유, 결과에 기반한 다음 행동.
경계: 여러 장비 슬롯과 합성 경제를 전부 추가하지 않는다.

2.8 Ballionaire, BALL x PIT [S13~S14]
확인: Ballionaire는 트리거와 연쇄, 규칙 변경, 실험실을 제공한다. BALL x PIT는 공 결합과 서로 다른 발동 조건·장단점의 조합을 강조한다.
적용: 충전→적중→날아감→벽 충돌처럼 원인이 읽히는 연쇄, 짧은 능력 시연, 공마다 다른 발동 조건.
경계: 영구 전투력 누적, 무한 증식, 합성으로 강화 티어 건너뛰기를 도입하지 않는다.

2.9 HannamBalls 공개 소스 [S15]
확인한 구간: effects.js의 지면 강타·균열·파편·얼음·잔상, battle-core.js의 저사양/모션 축소별 이펙트 상한과 HUD 갱신 주기.
적용: 효과별 재질과 방향, 표시 부하 제한, 저사양에서도 동일한 전투 판정 유지.
경계: DOM 기반 효과 코드를 현재 Canvas2D 엔진에 통째로 이식하지 않는다. 실명·사진·내부 캐릭터 표현은 기믹 참고와 분리한다.

조사에서 도출한 업데이트 순서
1) 선택과 판정의 정확성·복구 편의.
2) 읽히는 공격·방어·전투 결과.
3) 특성 하나로 달라지는 조합.
4) 같은 장면을 다시 확인하고 시험하는 도구.
5) 수업마다 다른 공 구성과 개인 성취.

3. 구현의 필수 기반: 기존 v2에서 유지할 것
======================================================================

이 기반이 없다면 아래 신기능보다 먼저 구현한다.

3.1 수업과 학생 상태
- 최대 학생 30명+호스트 1명. 기본 랭킹 도전 시간 15분, 교사 설정 5~30분.
- 방의 진행 상태와 학생별 퀴즈/강화/선택/대기열/경기 상태를 분리한다.
- 기본 강화권 10장은 세션에서 학생당 한 번. 재접속·새 공 생성·초기화로 재지급하지 않는다.
- 유효한 정답당 2장을 즉시 지급한다. 랭킹 모드의 기존 20문항 지급 제한을 없앤다.
- 오답은 설명과 재학습으로 이어지고, 같은 시도 재전송으로 보상을 받지 않는다.
- 아직 풀지 않은 문항 우선. 같은 문항의 보상 가능한 재출제는 마지막 응답 후 90초와 다른 문항 min(4, 문제은행 수-1)개 조건을 모두 만족해야 한다.
- 작은 문제은행에서는 복습·강화·경기로 이동할 수 있고 다음 보상 시점을 알려 준다.
- 승리/실패/출석/문항 묶음 완료에 추가 강화권을 지급하지 않는다. 이 경제의 재화 원천은 기본 10장과 정답 2장이다.

3.2 인벤토리
- 독립된 공 슬롯 3개. 첫 슬롯 T20 시작, 나머지 빈 슬롯에 무료 T20 생성 가능.
- 보관은 복사가 아니다. 강화 전의 강한 상태를 복제하거나 무료로 복구하지 않는다.
- 보관 잠금: 출전은 가능하지만 강화·교체는 명시적으로 잠금을 해제해야 가능.
- 한 공의 초기화는 다른 공·공통 지갑·유지권·퀴즈 진행·랭킹에 영향을 주지 않는다.
- 전투 패배는 공을 파괴하거나 티어를 낮추지 않는다. 새 경기에서는 체력·쿨다운·전투 자원을 초기화한다.
- 출전 스냅샷을 확정한 공은 대기열·경기 중 강화/특성 변경/삭제 불가. 다른 슬롯과 퀴즈는 사용 가능.
- 대기열 취소와 경기 배정이 겹치면 서버에서 먼저 확정한 상태가 우선한다.

공 선택·히든의 기존 규칙
- T18부터 각 목표 티어에 실제 사용 가능한 후보 최소2개.
- T10에서 화염, 물결·빙결, 번개, 대지, 자연, 검술, 공간·별빛, 소환·잔영의 성장 방향 선택.
- T10~T1은 선택한 방향의 공과 공용 공을 제공. 공용 공을 택해도 성장 방향은 보존.
- 전체 콘텐츠 목표에서 각 고급 티어에 경로 전용 최소3개+공용 최소6개를 제공한다.
- 폼·경로·히든·필수 특성 선택이 끝나기 전 그 공의 다음 강화와 대기열 참가를 막는다. 다른 슬롯과 퀴즈는 사용 가능.
- 히든은 슬롯별 세션 최초 T10 도달 때 1%로 한 번 판정. 랭킹3슬롯이면 최대3회.
- 초기화·삭제·재생성·재접속으로 해당 슬롯의 히든 판정 원장을 초기화하지 않는다.
- 토너먼트/럼블은 단일 출전 공의 세션 최초 T10 도달1회만 판정.
- 히든은 특수한 기믹이지 무조건 승리권이 아니다. 공 초기화 시 히든 능력은 소멸하고 발견 기록만 남는다.

3.3 랭킹·매칭
- 학생별 시작 레이팅 1000, Elo K=32. 실시간 학생 간 완료된 정식 경기만 반영.
- 동일 레이팅의 승패는 +16/-16. 무승부는 기존 Elo 무승부 규칙.
- 퀴즈 수, 티어, 도감, 특성 사용, 연출 감상 자체는 Elo를 올리지 않는다.
- 준비한 학생끼리 가중 무작위 매칭. 대기 시간 우선, 최근 상대 회피, 레이팅·출전 공 체급은 완만한 조건.
- 정확히 같은 티어만 매칭하는 고정 리그로 쪼개지 않는다. 15초 이상 기다리면 조건을 완화한다.
- 봇이나 저장 상대와의 연습을 실제 학생 랭킹전으로 처리하지 않는다.
- 정산은 matchId당 한 번. 양쪽 클라이언트의 결과 신고를 승패 근거로 쓰지 않는다.
- Top10을 호스트와 학생에게 제공하고, 10위 밖 학생의 내 순위·점수·최근 변화도 고정 표시한다.

3.4 모드·관전
- 랭킹/토너먼트: 학생은 자신의 경기 관전 가능. 호스트는 현재 경기 하나를 선택해 송출.
- 럼블: 30개 공 전체 시뮬레이션은 호스트만 표시. 학생은 자기 공 정보·생존/탈락·최종 순위·누구에게 탈락했는지 표시.
- 토너먼트/럼블은 기존 한 차례 퀴즈→강화→한 공 출전 흐름을 유지한다.
- 강화 확률·실패·유지권·성공 순서·전투/HUD는 모든 모드에서 공유한다.
- 반복 퀴즈·3슬롯·Elo 순환은 랭킹 모드의 기능이다.
- 정식 1:1은 20~35초를 목표로 하며 최대 40초, 30초부터 교착 해소 규칙을 적용한다. 수치는 플레이 검증 후 조정한다.
- 교사 일시정지는 논리 시간을 멈춘다. 종료 시 DRAINING으로 전환해 신규 강화·보상 지급·대기열·매칭을 차단하고 진행 경기와 이미 승인된 강화의 선택만 정리한다.
- DRAINING에서는 기존 resultId에 연결된 경로/공/특성 선택만 허용한다. 새로운 결과를 추첨하지 않는다.
- 정리 종료 시 남은 선택은 규칙 버전에 고정된 합법적 기본 후보로 확정한다. 미응답 히든은 거절한다. 자동 확정 결과를 최종 화면에 표시한다.
- 종료 후 정리는 일시정지 시간을 제외한 45초 이내. 미완료 경기는 규정에 따라 무효 처리한다.

4. 강화 확률: 전 단계 실패 가능, 최종 3%
======================================================================

4.1 단일 기준
- 표시 티어: T20이 시작, T1이 최종. 내부 level=20-tier.
- 확률은 성공하면 도달하는 '목표 티어' 기준.
- 강화 1회는 강화권 1장. 성공/실패 모두 1장 소비.
- 모든 수치와 판정은 서버의 한 경제 설정에서 읽는다. UI용 확률을 별도로 하드코딩하지 않는다.

T20 → T19 | 95%
T19 → T18 | 92%
T18 → T17 | 90%
T17 → T16 | 88%
T16 → T15 | 85%
T15 → T14 | 82%
T14 → T13 | 80%
T13 → T12 | 78%
T12 → T11 | 75%
T11 → T10 | 72%
T10 → T9  | 68%
T9  → T8  | 60%
T8  → T7  | 52%
T7  → T6  | 44%

4.2 실패: 시도 직전 '현재 티어' 기준
- 현재 T20: T20 유지. 더 아래 티어는 없고 강화권 1장은 소비한다.
- 현재 T19~T11: 한 단계 하락. 예: T15에서 T14 도전 실패 → T16.
- 현재 T10~T2: 해당 공을 T20으로 초기화.
- 현재 T1: 강화 완료. 강화 명령 거절, 비용 미차감.
- 경계: T11→T10 실패는 T12. T10→T9 실패는 T20.
- 무보호 초기화는 해당 공의 폼·경로·전투 스탯·히든·전술 효과를 초기화한다.
- 한 단계 하락은 해당 공의 이전 낮은 단계 선택 이력으로 폼을 복원한다. 그 티어에 존재하지 않는 고급 폼을 유지하지 않는다.
- 정상 생성된 공은 이전 단계 이력을 가진다. 이전 데이터 이전 등으로 이력이 없으면 해당 티어의 유효한 기본 대체 폼을 규칙으로 결정하고 문서화한다.
- 발견 기록과 이전 특성 선호 기록은 UI 기록일 뿐, 초기화된 공의 전투 성능을 유지시키지 않는다.

4.3 강화 유지권
- 유지권 한 종류, 1개 가격은 강화권 2장.
- 필요한 개수는 목표 티어 기준. 실제 하락/초기화를 막은 실패에서만 전량 소비한다.
- 성공 시 유지권을 소비하지 않는다.

시도 | 보호 필요 개수 | 보유가 0개일 때 보호+강화에 필요한 강화권
T20→T19 | 0, 보호 불필요 | 1장
목표 T18~T5 | 1개 | 3장
목표 T4~T2 | 2개 | 5장
목표 T1 | 3개 | 7장

예: T6→T5는 유지권 1개, T5→T4는 2개, T3→T2는 2개, T2→T1은 3개.
필요 개수만큼 보유하고 있다면 강화 시도 자체는 강화권 1장만 필요하다.

UI 계약
- 성공률, 현재→목표, 무보호 실패 결과, 이번 보호 필요 수, 보유 수, 부족분 구매비, 강화비를 같이 표시한다.
- 예: '보유 2개 / 이번 보호 3개 / 부족 1개 구매 2장 / 강화 1장'.
- '보호하고 강화'는 부족분 구매와 1회 시도를 원자적으로 처리한다. 비용을 버튼에서 읽을 수 있어야 한다.
- 보호 ON인데 부족하면 요청을 거절한다. 자동 무보호 전환, 일부만 소비하고 초기화하는 처리는 금지.
- 무보호 시도는 별도로 명확히 선택한다. T10부터 초기화 결과를 버튼 가까이에 표시한다.
- T20 바닥 실패에서는 보호 효과가 필요 없으므로 유지권을 소비하지 않는다.
- 단일 유지권 가격을 티어마다 바꾸지 않는다. 낮은 티어에서 사서 상위 비용을 우회하는 문제가 없도록 개수로 조정한다.

4.4 확률의 정직한 표시
- 숨은 성공률 조정, 가짜 아슬아슬한 실패, 연패 후 강제 성공, 숨은 천장은 추가하지 않는다.
- 이번 버전에는 강화 확률 증가 특성·시간대 이벤트·승리 강화권·티어 건너뛰기를 추가하지 않는다.
- 확률을 바꿀 경우 방 시작 전에 공개된 경제 버전을 고정하고, 이미 시작한 방에는 소급 적용하지 않는다.
- 동일 commandId 재시도는 같은 결과. 성공 연출이나 재접속 시 다시 추첨하지 않는다.

5. 확률 분석: 단일 시도와 한 수업의 도달률을 구별한다
======================================================================

5.1 왜 이전 제안을 수정하는가
이전 v2의 T1 10%와 모든 상위 보호 비용 2장 조합에서,
한 공에 집중하고 T10부터 계속 보호하며 부족하면 멈추는 정책의 T1 도달률은:
50장: 6.256%, 70장: 25.844%, 90장: 50.615%, 100장: 60.955%.
최종 시도 성공률이 10%라는 사실만으로 최종 공이 희귀해지지 않는다.

5.2 분석 방법과 가정
- 유한 상태의 전체 확률을 합산하는 동적 계획법. 일부 표본만 뽑는 Monte Carlo가 아니다.
- 공 하나를 T20에서 시작. 기본 10장+정답당 2장.
- 정책 A: T10 전 무보호, T10 이후 필요한 유지권 확보, 보호할 자원이 부족하면 중단.
- 정책 B: 미래 난수를 모르는 상태에서 T1 도달 확률만 최대화하도록 구매/보호/무보호를 선택.
- 성공 시 유지권 보존, 실제 보호 실패 시 요구 개수 소비. T1 도달 시 중단.
- 다른 슬롯 투자, 재화 보너스, 천장, 복제, 거래, 시간 비용 제외.
- 정책 B는 이 한 공 모형의 최적치다. 모든 3슬롯 전략의 엄밀한 상한은 아니다.
- 기본 DP의 확률 합을 검증했고, 정책 A의 30/50/70/90/130/170장 결과는 Fraction 계산과 교차 확인했다.

5.3 새 제안의 도달률

총 강화권 | 정답 수 | 정책 A T5 이상 | 정책 A T3 이상 | 정책 A T1 | 정책 B T1
30 | 10 | 28.411% | 0.944% | 0.000878% | 0.006302%
50 | 20 | 87.226% | 17.636% | 0.0994% | 0.2142%
70 | 30 | 98.880% | 47.195% | 0.7945% | 1.2116%
90 | 40 | 99.925% | 71.043% | 2.6369% | 3.4439%
130 | 60 | 99.9997% | 92.911% | 9.9416% | 11.3537%
170 | 80 | ≈100% | 98.445% | 20.1507% | 21.7771%

T10 이후 보호하여 티어가 내려가지 않는 정책 A에서 T5/T3 도달은 현재 보유 확률과 같다.
위 숫자는 학생 플레이 실측치가 아니다. 한 공에 자원을 집중하는 경제 벤치마크다.
두 정책 사이 수치를 '범위'로 요약할 때는 정책 차이라고 밝힌다. 신뢰구간이 아니다.

5.4 학급 전체의 희소성
30명이 모두 같은 예산과 정책을 쓰고 강화 난수가 독립이라는 가정:
학급에서 한 명 이상 T1 = 1 - (1 - 개인 T1 확률)^30.

총 강화권 | 정책 A에서 학급에 T1 한 명 이상 | 정책 B에서 학급에 T1 한 명 이상
50 | 2.94% | 6.23%
70 | 21.28% | 30.63%
90 | 55.14% | 65.05%
130 | 95.68% | 97.31%
170 | 99.88% | 99.94%

권장 해석: 70장 정도면 학생 개인에게 T1은 드물고, 학급에서도 매번 나오는 이벤트가 아니다.
130장 이상을 빨리 공급하는 문제은행이나 긴 수업에서는 T1이 더 자주 나온다.
양수의 확률과 반복 가능한 보호를 유지하면서 무한 재화에서도 영원히 희귀하게 만들 수는 없다.
따라서 3%는 15분 기본 세션을 위한 시작값이다. 어떤 시간·공급 조건에서도 희귀하다는 보장이 아니다.

5.5 초반 실패가 성장을 막는가
초기 10장, 초반 무보호일 때:
- 첫 두 번 연속 성공: 87.4%.
- T18을 한 번이라도 경험: 99.9987%.
- 10장 사용 후 현재 T18 이상: 99.9453%.
- T15을 한 번이라도 경험: 95.9868%.
- 10장 사용 후 현재 T15 이상: 89.9289%.
- T10 도달: 16.2573%.
- T10 최초 도달에 필요한 티켓 중앙값 14장, 90백분위 22장.
첫 두 번을 보장하지 않아도 재시도를 통해 첫 선택과 성장 경험에 도달하기 쉽다.

5.6 15분 수업 시간 예시 — 실측 아님
정답률 80%를 가정하고 정답 수의 이항분포를 모두 합산했다.
아래 강화·선택 시간에 실제 조작이 끝난다고 가정한다. 클릭 속도와 주의 전환 전체를 모델링하지 않았다.
전투가 배경에서 진행되는 시간을 중복 차감하지 않고, 집중해서 관전하는 시간만 배분했다.

예시 | 퀴즈/문항 | 강화·선택/관전/이동 | 기대 정답·티켓 | T1, A/B
천천히 | 450초/18초 | 210/180/60초 | 20개·50장 | 0.111% / 0.230%
보통 예시 | 540초/14초 | 150/150/60초 | 30.4개·70.8장 | 0.880% / 1.315%
빠르게 | 600초/12초 | 120/120/60초 | 40개·90장 | 2.689% / 3.494%
빠른 수급 스트레스 | 600초/8초 | 120/120/60초 | 60개·130장 | 9.985% / 11.391%

최종 5%라면 70장 T1이 1.299~1.974%, 최종 2%라면 0.535~0.817%다.
3%를 권장하되 학생 정답 수와 실제 소요 시간을 먼저 측정한 뒤 다음 경제 버전에서 조정한다.
무제한 보호 육성의 T1 평균 비용 약354.05장은 수업 목표가 아니다. 긴 꼬리를 가진 반복 비용의 평균이다.

6. 중간 티어의 재미와 최종 티어의 가치
======================================================================

6.1 현재 성장 곡선에서 유지할 장점 [S1]
level=20-tier, 폼/클래스 배율 적용 전:
HP = 200 + 6×level, 기본 공격 계수 = 10 + 0.5×level.
티어가 높아진다는 이유만으로 기본 이동 속도가 증가하지 않는다.

티어 | 기본 HP | 기본 공격 계수
T20 | 200 | 10
T10 | 260 | 15
T5 | 290 | 17.5
T3 | 302 | 18.5
T1 | 314 | 19.5

T1은 T5보다 HP 약8.28%, 공격 계수 약11.43% 높다.
T1은 T3보다 HP 약3.97%, 공격 계수 약5.41% 높다.
이는 같은 배율 조건의 산술 비교이며 승률이 아니다. 실제 공격 종류·명중·방어·쿨다운·속성이 추가된다.
새 확률과 함께 상위 스탯을 갑자기 두 배로 올리지 않는다. 먼저 이 완만한 곡선을 유지하고 기믹을 검증한다.

6.2 티어별 경험 목표
T20~T19: 재육성 출발. 기본 반사와 충돌. 상위 공과 대등하다고 설명하지 않는다.
T18~T16: 첫 공 선택, 대표 공격 하나를 실제로 경험. 공마다 다른 실루엣·무기 궤적.
T15~T11: 같은 계열의 외형/예고/공격 리듬이 완성되어 다음 전직을 기대할 수 있음.
T10~T6: 경로·속성·특성 선택. 보관할 주력 공으로 사용할 수 있는 구간.
T5~T3: 계열의 핵심 연계와 대응법이 완성된 실전 목표.
T2: 최종 도전의 직전 성취. 보관할지 더 도전할지 의미 있는 선택.
T1: 드문 완성형. 특별한 성공·입장·무기·코어 연출과 검증된 조건부 각성.

T1에만 모든 흥미로운 능력을 몰아넣지 않는다.
T1의 보상은 단순 HP 몇 점만으로 끝나지 않되, 전 속성 우위·상시 무적·상시 공격 배증을 주지 않는다.
조건부 각성은 대표 프로필부터 검증해서 확대한다. 미구현 각성을 도감 문구로만 약속하지 않는다.

6.3 실패 뒤에도 선택이 남는 구조
- T5 보관 공으로 랭킹전을 이어가며 다른 슬롯에서 T1을 도전할 수 있다.
- '주력 공 보관 / 다른 상성 공 육성 / 최종 단계 집중'이 실제 자원 배분의 선택이다.
- 유지권은 상위 초기화 비용 때문에 기대 비용상 유리한 경우가 많다. 보호 토글 자체를 깊은 전략이라고 과장하지 않는다.
- 초기화 결과 화면에는 보관 공 출전, 문제 풀기, 해당 코어 재육성의 다음 행동을 제공한다.
- 무료 이전 상태 복구나 공 복제로 실패의 의미를 없애지 않는다.

6.4 속성 표시의 정확성 [S1]
- 현행 유리 속성 피해 ×1.20, 불리 속성 ×0.85를 시작값으로 유지.
- 화염→자연→대지→번개→물결→화염 관계를 화면에서 확인 가능하게 한다.
- 성장 경로, 클래스의 외형, 실제 출전 속성은 다른 값일 수 있다.
- 현행 공용 폼과 T18~T11 폼은 무속성이다. 물방패처럼 보여도 자동으로 물 상성 보너스를 주지 않는다.
- 도감·인벤토리·HUD·피해 설명은 최종 build.element를 공통으로 참조한다.
- '공격력' 수치는 기본 공격 계수라는 뜻을 설명하고, 대표 기술의 계수·발동·방어 조건을 별도로 보여 준다.

7. 새 선택 시스템: 전술 특성 1칸
======================================================================

7.1 기본 규칙
- T10 도달 후 공당 전술 특성 1개 활성화. 추가 재화·희귀도·특성 가챠 없음.
- 각 전투 프로필에 고정된 호환 후보 3개를 정의하고 그중 선택.
- 메뉴를 다시 열어도 후보가 바뀌지 않는다. 무료 리롤을 위해 초기화할 이유를 만들지 않는다.
- 인벤토리에서 대기열에 들어가기 전 무료 변경 가능.
- 강화 후 같은 특성이 호환되면 유지. 새 공과 호환되지 않으면 다시 선택해야 READY가 된다.
- 히든 선택이 있다면 최종 공 결정 후 특성을 확인한다. 선택을 두 번 요구하지 않는다.
- 초기화 시 특성 효과는 해제. 이전 선택은 편의용 선호 기록으로만 남긴다.
- 매 경기 준비 때 다시 고르라고 묻지 않는다.
- 특성은 강화 확률, 퀴즈 보상, Elo 계산을 바꾸지 않는다.

7.2 초기 특성 카탈로그: 10개 설계 후보
아래 수치는 첫 구현의 조정 시작값이며 확정 밸런스 결과가 아니다.
각 프로필의 기존 기믹과 중복·무효이면 그 후보를 제외하고 호환표에서 다른 후보를 지정한다.

ID / 이름 | 행동 변화 예시 | 제약·대가
wall_charge / 벽 축전 | 유효 벽 반사 3회 후 다음 직접타 강화 | 충전 1개 상한, 기본 직접 피해 소폭 감소, 일반 벽 접촉 피해는 생성하지 않음
stability / 무게 중심 | 피격 넉백에 덜 밀리고 자세 회복이 빠름 | 기본 이동 속도 소폭 감소, 넉백 면역 아님
impact_rhythm / 연계 박자 | 일정 시간 내 유효 직접타 3회 뒤 강화된 다음 타격 | 직접타만 집계, 추가타가 스스로 다시 충전 불가, 평타 계수 소폭 감소
guard_riposte / 반격 준비 | 유효 방어 뒤 짧은 반격 충전 | 방어 효율 일부 감소, 충전 상한1, 반사→반격 재귀 불가
long_reach / 긴 무기 | 회전 무기의 실효 사거리 확대 | 회전 속도 감소, 실제 히트박스와 그림 동일
quick_return / 회수 숙련 | 던진 무기가 실제 귀환하면 다음 준비시간 단축 | 비행 중 피해 감소, 귀환 없는 공에는 제시하지 않음
residual_heat / 잔열 | 고유 화염 직접타 뒤 짧은 잔열 | 직접 피해 일부 감소, 지속 피해 중첩/발동 상한
frost_fracture / 빙결 균열 | 감속 중인 상대의 표식을 쌓아 파쇄 | 감속 지속시간 감소, 지속 피해·소환·반사로 표식 생산 불가
pulse_focus / 집중 포격 | 예고가 길어지는 대신 유효 공격폭 또는 관통 조건 개선 | 차지형 공 전용, 공격 예고와 실제 판정 일치
squad_focus / 소수 정예 | 동시 소환 수를 줄이는 대신 개체 행동 강화 | 소환 수 상한 감소, 소환 없는 공에는 제시하지 않음

공통 특성도 숫자만 바꾸는 설명으로 끝내지 않는다. 넉백·발동 리듬·유효 사건에 변화가 있어야 한다.
정확한 계수는 규칙 데이터에서 정의하고 설명을 동일 데이터에서 생성한다.
대표 8개 프로필로 먼저 구현·검증한 다음 지원 프로필의 호환표를 확대한다.
- 중간 검토 버전에서는 검증된 공 구성으로 제한하거나 방 전체의 특성 기능을 끈다. 일부 학생에게만 미완성 특성을 켜지 않는다.
- 최종 특성 활성화 릴리스는 선택 가능한 모든 T10~T1 프로필에서 유효한 후보3개를 검증해야 한다. 빈 특성 창으로 READY를 막지 않는다.
신규 24개 프로필과 10개 특성 전체를 무차별 조합한 뒤 밸런스 책임을 남기지 않는다.

7.3 전투 내 성장과 상한
일부 공은 한 경기 안에서 조건을 쌓아 짧게 강해질 수 있다.
- 철퇴: 벽 반사 충전→직접 강타→실제 넉백→허용된 벽 충돌 추가 피해.
- 방패: 유효 방어 축적→읽히는 반격 준비→조건을 만족한 다음 공격.
- 검: 유효 적중 리듬→짧은 강화 검기. 무한 사거리·무한 공속으로 커지지 않음.
- 과열 포격: 반복 발사로 열 증가→강한 사격→냉각 중 빈틈.
- 희생형: 제한된 HP 소모로 짧은 강점. 다음 경기까지 능력치 이월 없음.

모든 프로필에 같은 분노 게이지를 추가하지 않는다.
공마다 전투 자원 표시를 최대 하나로 요약하고 현재/상한/발동 준비를 HUD에 보여 준다.
충전·스택·쿨다운·상태는 새 경기에서 완전히 초기화한다.

발동 계약
- sourceEventId/rootAttackId를 둬 동일 타격 중복 집계를 막는다.
- 직접타, 지속 피해, 반사, 소환 공격, 파생 효과를 태그로 구별한다.
- 기본적으로 파생 효과는 다시 특성 발동을 일으키지 않는다. 예외는 명시한 유한 연계만 허용.
- 광역 공격은 적 수만큼 무제한 충전하지 않도록 rootAttackId 단위 집계 상한을 둔다.
- 벽에 끼인 매 프레임을 새로운 벽 반사로 세지 않는다.
- 충전 상한, 최소 재발동 간격, 유지 시간, 대상 변경/사망 시 정리 규칙을 정의한다.
- 선제 적중이 계속 성장으로 이어지는 일방적 눈덩이를 좌우 교환·같은 시드 검사로 점검한다.

8. 전투 Game Feel: 강도와 인과관계를 함께 전달
======================================================================

8.1 대표 8개 장면을 품질 기준으로 만든다
1) 철퇴 강타와 벽 충돌.
2) 연속 검격과 짧은 피격.
3) 전방 방패 방어와 반격.
4) 차지 포격과 발사 반동.
5) 돌진의 예고·명중·빗나감.
6) 빙결·감속 표식과 파쇄.
7) 소환체의 등장·실제 공격·해제.
8) 공간 이동 또는 흡수·되돌려 주기.

모든 공격에 큰 넉백과 화면 흔들림을 붙이는 방식으로 완료하지 않는다.
강타는 무겁게, 연타는 짧고 촘촘하게, 흡수는 방향성 있는 수렴으로, 방어는 충돌면의 반응으로 구별한다.

8.2 공격별 표현 계약
- 예고: 무기 뒤로 젖힘, 차지, 궤도, 공격 방향 중 실제 발동에 맞는 신호.
- 접촉: 실제 충돌점의 순간 섬광·짧은 변형·재질별 소리.
- 이동: 물리 결과에 대응하는 넉백, 잔상, 짧은 속도선.
- 벽: 허용된 강타에서만 벽 흔들림·파편·벽 피해. 일반 반사에는 작은 효과.
- 결과: 피해 숫자와 상단 HP 감소가 같은 전투 시점에 보임.
- 가드: 막은 위치와 방패 잔량, 파괴 시 명확한 깨짐.
- KO: 마지막 유효 사건을 짧게 강조. 이미 끝난 결과를 다시 판정하지 않음.

8.3 물리와 화면
- 기존 move()의 기본 속도 회복과 피격 넉백 속도를 분리한다.
- 기본 이동 속도+넉백 속도, 질량, 감쇠, 속도 상한을 명시한다.
- 강한 벽 충돌 후 무한 왕복 피해, 벽 끼임, 공 겹침, 바깥 이탈을 막는다.
- 공격 쿨다운과 같은 접촉의 중복 피해 제한은 시뮬레이션에서 처리한다.
- squash/stretch와 화면 흔들림은 시각 표현이며 충돌 반지름을 몰래 바꾸지 않는다.
- 화면을 흔들어도 상단 체력 HUD는 고정한다.

8.4 히트스톱·슬로모션
- 서버의 권위 시뮬레이션과 방 시간을 화면 효과 때문에 멈추지 않는다.
- 기본 v2의 제한된 표시 지연 모델을 유지: 1회 히트스톱 최대100ms, 1초당 누적120ms 이내를 시작 예산으로 삼는다.
- 위치·HP·피해 숫자·효과는 동일 presentationTick에서 표시한다. HP만 미래로 진행하거나 충격만 과거에 남으면 안 된다.
- 표시 지연이 쌓이면 상한 내에서 부드럽게 복구한다. 경기를 계속 느리게 만드는 효과 누적은 금지.
- 긴 KO 슬로모션은 확정된 경기의 선택적 하이라이트에서 제공한다.
- 0.5/1/2배속은 리플레이·실험실 전용. 개인이 실제 경기 시간이나 상대 진행을 바꾸지 못한다.

8.5 시각·음향·접근성
- 흰색 전장, 뚜렷한 경계, 공·무기의 실루엣을 유지한다.
- 공격 재질별 소리: 몸체/금속/방패/에너지/벽/KO. 음량만 키워 강타를 만들지 않는다.
- 반복 충돌 소리의 동시 재생 수와 짧은 발동 간격을 제한한다. 같은 음색에 소규모 변주를 줄 수 있다.
- 음향 난수는 전투 RNG를 소비하지 않는다.
- 음악/효과음 분리, 기본 음량 제어, 모션 줄임, 저사양 모드를 지원한다.
- 한 순간의 다중 효과보다 공·무기·HP를 먼저 보이게 한다.
- 의성어 텍스트를 타격감 대신 넣지 않는다.
- 재접속·백그라운드 탭 복귀 시 지나간 타격 소리를 한꺼번에 재생하지 않는다.
- 이펙트를 줄여도 실제 공격·상성·승패는 변하지 않는다.

8.6 상단 격투게임 HUD
- 1:1 양쪽에 긴 파란 HP바. 피격분은 빨간 잔상으로 남았다가 빈 공간으로 줄어듦.
- 시작값: 피해 잔상 대기200ms, 따라 줄어듦450ms. 연속 피격으로 빨간 잔상이 영원히 유지되지 않도록 최대 지연900ms.
- 회복, 최대 HP 변경, 관전 대상 변경, 새 경기 시 잔상 상태를 정확히 재설정.
- 공 아래에는 플레이어 이름만. 능력·체력·속성·티어는 상단 카드에 배치.
- 상태 표시는 아이콘+짧은 이름/수치. 색만으로 속성과 상태를 구분하지 않는다.
- 럼블 호스트는 30개 긴 HP바를 같은 방식으로 붙이지 않는다. 선택/주목 공 정보와 생존 수, 읽을 수 있는 간략 목록을 사용한다.

8.7 외형 복원과 T1 성취
- orb/portrait/hybrid 세 렌더를 같은 전투 프로필에 연결한다.
- 과거 23c5c341e5b105c9711635870f53d14895d4921f의 skin() 장점을 별도 재질 모듈로 복원한다.
- 과거 arena.js 전체를 덮어써 현재 무기·소환·보간 코드를 잃지 않는다.
- 금속·유리·핵·전기·얼음 등의 재질과 실제 무기 실루엣을 함께 사용한다.
- T1 성공·입장 효과는 알아볼 수 있어야 하며 퀴즈 화면을 강제로 가리거나 모든 관전자에게 긴 영상을 강요하지 않는다.
- 애니·만화·영화의 원형은 능력의 행동과 장단점으로 재해석한다. 단순 이미지 교체를 신규 기믹으로 세지 않는다.

9. 능력 미리보기, 최근 경기, '왜 졌지?' 연습
======================================================================

9.1 6초 능력 미리보기
- 공 후보/도감에서 한 번 눌러 보는 짧은 시연. 자동 재생을 모든 카드에 동시에 켜지 않는다.
- 동일 공통 시뮬레이터와 규칙을 사용한다.
- 필요한 상황을 만든 시연 시나리오로 예고→기술→명중/방어를 보여 준다.
- 준비 시간이 긴 기술은 시연용 초기 상태를 명시한다. 평소에도 6초 안에 항상 발동한다고 속이지 않는다.
- 시연은 능력 이해용, 승률 예측이 아니다.

9.2 최근 3경기 리플레이
- 정식 최근 경기 최대3개를 학생별로 접근 가능하게 한다.
- matchId, 초기 출전 스냅샷, RNG 시드, rulesetVersion, contentVersion, 서버 확정 상태/이벤트를 보존한다.
- 현재 세션의 최근3경기는 서버 확정 상태와 이벤트를 보간하는 기본 재생 경로로 실제 관전이 가능해야 한다. 정상 기록 대부분을 '재생 불가'로 남기지 않는다.
- 결정론적 재시뮬레이션은 원본과 일치하는지 해시/결과 검증을 통과할 때 활용한다.
- 버전이 달라 동일 재시뮬레이션이 불가능하면 기록된 상태 기반 재생을 사용한다. 해당 기록에 필요한 표시 메타데이터도 보존한다.
- 예외적으로 데이터 손상이나 지원 종료로 재생 불가라면 원인을 알린다. 다른 버전에서 다시 돌린 결과를 원본 경기라고 보여 주지 않는다.
- 일시정지, 0.5/1/2배속, 3~5초 마지막 장면 선택적 보기.
- 리플레이를 열거나 끝까지 보아도 티켓·Elo·경쟁 성취를 재지급하지 않는다.
- 라이브 경기와 녹화 화면의 표제를 구분한다.
- 경기 단위 데이터를 중복 저장하지 않고 학생의 최근 목록은 참조로 관리한다.
- 메모리·개수·보존 기간 상한을 정한다. 영구 경기 아카이브를 이번 범위에 추가하지 않는다.

9.3 결과 설명
긴 로그 대신 실제 사건에서 뽑은 핵심3개를 기본 표시한다.
예: '철퇴 강타3회 / 벽 충돌 추가 피해42 / 상대 방패에 막힌 공격2회'.
- 발동 횟수, 실제 추가 피해, 방어량, 결정적 피격처럼 검증 가능한 값만 사용한다.
- 기본 공격 계수와 최종 피해량을 혼동하지 않는다.
- 데이터가 없는 이유를 추측해 '속성이 불리해서 졌음'으로 단정하지 않는다.
- 자세히 보기에서 원인 사건과 상태를 확인할 수 있다.
- 결과에는 같은 공 재도전, 다른 보관 공, 문제 풀기, 연습 버튼을 제공한다.

9.4 비교 연습
- 마지막 상대의 해당 경기 빌드 스냅샷을 상대로 현재 보유 공/특성을 바꿔 시험한다.
- 변경은 연습 전용 복사 스냅샷과 labOverride에만 적용한다. 실제 인벤토리 traitId와 대기/경기 중 출전 스냅샷을 수정하지 않는다.
- '실전에 적용'을 제공한다면 잠금 해제 후 현재 보유 공의 합법적인 특성 변경만 서버가 검증한다. 과거 강한 스냅샷을 실제 공으로 복구하거나 복제하지 않는다.
- 정식 원본 리플레이는 그대로 보존하고 별도 연습 실행을 만든다.
- 같은 시드를 선택해도 빌드 변경은 사건·난수 소비 순서를 바꿀 수 있다. 모든 미래 상황이 동일하다고 보장하지 않는다.
- 같은 상대에게 다음 정식 경기에서도 이긴다는 예측으로 표시하지 않는다.
- 실제 온라인 학생이 지금 참여한 것처럼 표시하지 않는다.
- 연습·도감 시연은 로컬에서 공통 sim으로 처리할 수 있으나 결과를 정식 서버 승점으로 제출하지 않는다.
- 기본 돌격/원거리/방어 연습 상대도 제공할 수 있다.
- 연습 도중 실제 매칭이 잡히면 즉시 정리하고 내 경기 알림으로 이어간다. 랭킹 대기 상태를 숨기지 않는다.

10. 반복 조작을 줄이는 편의성
======================================================================

10.1 강화 흐름
요청→서버 결과 확정→성공/실패 문구→결과 확인→필요한 경로 선택→공 선택→히든 제안→필요한 특성 선택→READY.
- 성공 문구가 반드시 먼저. 후보 카드를 뒤에 미리 클릭 가능하게 두지 않는다.
- 일반 성공600~800ms, 이정표1000~1200ms를 시작값으로 사용.
- 300ms 이후 다음 단계로 이동 가능. 모션 줄임에서도 문구와 순서 유지.
- 모든 성공에 긴 팝업을 강요하지 않는다. 다음 티어에 합법적인 동일 계열 후보가 있을 때만 '현재 계열 계속' 빠른 선택을 제공한다. 해당 후보가 없으면 정상 후보를 선택한다.
- 이전 폼을 임의로 상위 티어 스탯에 붙이지 않는다. 특성 자동 유지도 최종 profileId의 호환표를 확인한 뒤 적용한다.
- 선택 단계가 필요 없으면 생략하고, 이미 호환되는 특성을 매번 재확인하지 않는다.
- 강화 실패 후 정확한 티어 변화·유지권 소모·남은 자원을 표시한다.
- 결과와 후보는 commandId/resultId별로 보존한다. 재접속 시 남은 선택을 이어간다.

10.2 인벤토리·대기
- 최근 출전 공 기억, 보관 잠금, 이름/계열/속성/행동 필터, 짧은 비교.
- 현재 공에서 다음 티어에 가능한 후보와 대표 능력을 미리 확인할 수 있다.
- 등급 숫자가 낮을수록 강해지는 체계를 일관되게 표시한다. T20→T1 성장 경로를 제공한다.
- 준비 버튼에는 어느 공·특성이 출전하는지 표시.
- 대기 중 문제를 풀 수 있고 문제/선택/스크롤을 유지한다.
- 결과 알림과 Top10 갱신이 현재 입력을 빼앗지 않게 한다.
- 다른 화면에서 경기 중이어도 내 경기 바로가기와 짧은 상태를 유지한다.
- 네트워크 응답 전 반복 클릭은 같은 요청으로 취급하고 실제 결과를 기다리게 한다.

10.3 호스트 편의
- 남은 시간, 참가/연결 상태, 현재 경기 목록, Top10, 송출 선택.
- 송출 대상은 교사가 바꾸기 전까지 유지. 새 경기마다 자동으로 화면이 급변하지 않게 한다.
- 선택 경기 종료 시 결과를 짧게 표시한 뒤 다음 송출 후보를 제시.
- 선택하지 않은 다른15경기의 사운드를 동시에 재생하지 않는다.
- 일시정지·재개와 종료 정리 상태를 명확히 표시.
- 교사가 화면을 새로고침해도 같은 방의 권한과 진행을 복구할 수 있어야 한다.
- 새 기능 안내는 한 번의 짧은 도움말과 화면 내 정보로 제공. 수업마다 긴 튜토리얼을 요구하지 않는다.

11. 다음 수업에도 다른 선택을 해볼 이유
======================================================================

이 절은 P2다. 핵심 루프·전투·확률·특성이 검증된 뒤 진행한다.

11.1 교사 선택 수업 팩
- 입문 팩: 읽기 쉬운 강타/방어/포격/돌진 등 검증된 기믹.
- 전체 팩: 구현·호환성·밸런스 검증을 통과한 공.
- 테마 팩: 방어와 관통, 충돌과 반격 등 서로 대응 가능한 구성.
- 같은 방의 모든 학생은 같은 후보 풀. 시작 후 풀과 경제 버전 고정.
- 팩 검증: T18부터 목표 티어에 최소2후보, T10부터 활성 경로와 공용 후보가 충분해야 함.
- 기존 v2의 경로별 최소3개+공용 최소6개 조건을 충족하지 않는 팩은 시작을 막거나 설계 단계에서 수정한다.
- 제한 팩의 활성 경로만 전직에 표시. 들어가면 다음 티어 선택이 사라지는 막힌 경로 금지.
- 학생별 몰래 좋은 후보를 주는 보정은 넣지 않는다.

11.2 개인 성취와 도감
- 전체 순위와 별도로 내 최고 점수, 처음 발견한 계열, 실제 기믹 성공 기록을 보여 준다.
- 한 화면의 개인 목표는 최대3개. 예: 서로 다른 공2종 출전, 유효 방어 뒤 반격 성공, 새 개인 최고 점수.
- 목표는 정상 정식 경기의 이벤트로 판정하고 중복 matchId·재접속·리플레이에서 다시 지급하지 않는다.
- 도감·칭호·입장 표현 등으로 보상. 추가 티켓·영구 전투 능력치로 전환하지 않는다.
- 새 수업의 전투력·지갑·레이팅은 새로 시작한다.
- 계정 없는 환경의 장기 기록을 브라우저에만 보존한다면 기기 변경·데이터 삭제 시 사라짐을 정확히 알린다.
- 장기 계정·학생 개인정보 수집·교차 기기 동기화를 이번 작업의 숨은 필수 조건으로 만들지 않는다.

11.3 후순위 후보
- 대기 중 짧은 PvE, 작은 협동 보스, 교사용 공 프리셋 편집.
- 별도 재화 없이 즐길 수 있는 경우부터 검토.
- 자유 장비 합성, 두 번째 특성 슬롯, 실시간 조작, 길드, 상점 경제는 이번 핵심 범위에 포함하지 않는다.

12. 콘텐츠와 오픈소스 적용
======================================================================

12.1 기존 콘텐츠 목표와 이번 품질 기준
- 기존 v2의 26개 기존 프로필 정비+24개 신규 기믹 목표를 삭제하지 않는다.
- 구현 순서는 공통 전투 계약→대표8개 검증→기존 프로필 정비→신규 프로필 확장이다.
- 이번 명세가 별도의 신규50개를 더 요구하는 것은 아니다.
- 이름/색/초상화만 다르면 외형 변형으로 센다. 새로운 행동·조건·대응법이 있어야 신규 기믹으로 센다.
- 도감에는 실제 구현된 것만 '사용 가능'으로 표시한다.
- 각 프로필은 장점1개 이상과 읽을 수 있는 약점1개 이상을 문서화한다.

12.2 각 프로필의 계약
profileId, formId, classId, 티어, 활성 경로, 최종 속성, 기본 스탯,
공격 예고/판정/쿨다운, 넉백 성격, 방어 조건, 상태이상,
오브젝트 수명·상한, 전투 자원, 특성 호환3개, 피해 이벤트 태그,
외형 프리셋, 효과음, HUD, 시연 시나리오, 대응 가능한 상대, 테스트를 정의한다.

12.3 오픈소스 활용 방식
- HannamBalls는 효과 분리와 저사양 예산의 구현 참고로 활용한다.
- 이전 검토 후보 howler.js는 음향 관리가 현재 구조에서 실제로 필요할 때 선택한다.
- AetherFX/EffectCraft는 필요한 경우 효과 제작·스프라이트/플립북 참고로 평가한다. 런타임 의존성으로 무조건 추가하지 않는다.
- Unity/Godot 게임을 현재 브라우저 엔진에 통째로 이식하지 않는다.
- 채택 파일/라이브러리마다 출처, 버전/커밋, 라이선스, 사용 범위와 필요한 고지를 기록한다.
- 소스 코드와 포함 이미지/음원의 이용 조건을 각각 확인한다.
- 미확인 파일을 복사해 온 뒤 '오픈소스이므로 모두 자유 이용'이라고 가정하지 않는다.
- 실제 기여는 효과음 중복 제한, 재질별 효과, 충돌 판독성, 리플레이 신뢰성처럼 관찰 가능한 변화로 보고한다.

13. 데이터·서버·구현 경계
======================================================================

기존 엔진과 공통 sim을 우선 확장한다. 거대한 프레임워크 교체를 이 업데이트의 선행 조건으로 만들지 않는다.

권장 변경 지도 — 실제 파일 배치는 현재 코드와 AGENTS.md를 확인해 조정
- packages/content/economy.js: 이번 확률표, 보호 필요 수, 명시적 경제 버전.
- packages/content/forge.js: 실패 경계, 원자적 비용, 선택/초기화/특성 상태.
- packages/content/traits.js 또는 동등 모듈: 고정 특성 정의, 호환표, 표시 정보.
- packages/content/classes.js / balls.js: 실제 속성·폼·진화·시연·프로필 계약.
- packages/sim/arena.js 및 분리 모듈: 실제 충돌, 넉백, 발동 훅, 상한, 이벤트 원인.
- apps/server/room.js와 학생/매칭 모듈: 세션과 학생 상태 분리, 지급·대기·정산의 권위.
- public/session*.js: 성공 우선 순서, 지갑, 후보/특성, 재연결 복구.
- public/arena.js와 HUD/FX 모듈: 동일 표시 시점, 상단 HP, 저사양·음향 예산.
- replay/lab 모듈: 버전 고정 재현, 기록 보존, 비경쟁 실행.

필수 서버 계약
- 퀴즈 정답·강화 RNG·재화·매칭·승패·Elo는 서버 권위.
- 정답 키, 복구 토큰, 다른 학생의 비공개 지갑/문항 원장을 공개 상태에 포함하지 않는다.
- 퀴즈 제출·유지권 구매+강화·후보 선택·대기열 참가·정산에 원자성과 중복 방지를 둔다.
- 잔액은 음수가 될 수 없다. 동시에 두 슬롯에서 강화해 같은 티켓을 중복 소비하지 않는다.
- 매칭 후 출전 스냅샷은 고정. 이후 학생이 다른 슬롯을 바꿔도 현재 경기 불변.
- 피격 효과, 오디오, 입자 난수는 판정 RNG와 분리한다.
- 학생에게는 자기 경기 상태, 호스트에게는 선택 경기 상태만 전송. 모든 학생에게15경기 전체 이벤트를 보내지 않는다.
- 럼블 학생 화면에는 거대한 전장 상태를 보내지 않아도 개인 결과를 제공할 수 있게 한다.
- 탭 복귀·재접속은 최종 권위 상태와 남은 선택/결과를 동기화한다. 지나간 명령 재실행 없음.
- 선택 중 세션 종료: DRAINING 동안 이미 승인된 결과의 선택만 허용. 정리 종료 시 합법적 기본 후보로 확정하고 미응답 히든은 거절한다. 확정한 티어는 보존하며 신규 정식 출전은 막는다.
- 폼/특성 미완결 상태를 유효 빌드로 출전시키지 않는다. 자동 기본 선택은 해당 경제/콘텐츠 버전의 고정 규칙으로 재접속에도 같아야 한다.
- 서버 재시작까지 방 복구를 지원하는지 명시한다. 단순 브라우저 재접속 복구와 영구 저장을 같은 기능으로 보고하지 않는다.

16. 수업 검증 지표와 조정 기준

다음 값은 앞으로 측정할 지표다. 이미 달성한 수치가 아니다.
- 첫 공 선택/T10/T5 도달까지 시간과 사용 티켓.
- 정답 수·문제은행 크기·문항 소요 시간별 T1 최초 도달률.
- 학급당 T1 인원과 한 명 이상 나오는 빈도.
- 강화 초기화 뒤 보관 공 출전/재육성까지 걸린 시간.
- 패배 뒤 다시 준비한 비율, 두 번째/세 번째 공을 사용한 비율.

- 전투보다 선택/메뉴에 과하게 시간이 쓰이는지.
- 실전 승률과 티어·속성·기믹별 편향.

조정 원칙
- 먼저 학생이 막히는 UI와 사용되지 않는 기믹을 고친다.
- 최종 도달이 과도하게 흔하면 티켓 실제 공급량과 유지권 규칙을 함께 검토한다.
- 기본 보상10+정답2를 유지한 채, 공개된 다음 경제 버전에서 확률/필요 유지권을 조정할 수 있다.
- 특정 학생에게만 몰래 확률을 낮추거나 다음 승리를 보장하지 않는다.
- 최종 도달이 너무 드물다는 이유만으로 모든 재미를 T1에 더 몰지 않는다. 중간 성취를 보강한다.
- 체험자가 최종 티어를 못 얻어도 '다음에는 다른 공/특성으로 해보겠다'고 느끼는지 확인한다.

부록 A. 경제 계산을 재현하는 상태 전이
======================================================================

정책 A 상태: (사용한 티켓, 현재 level, 보유 유지권), 필요하면 최고 level 기록 추가.
level=0은T20, level=19는T1.
목표 tier=19-level.
보호 필요 수: 현재level0이면0, 목표tier>=5이면1, 목표tier>=2이면2, 목표tier1이면3.
정책 A는 현재level>=10에서 보호, 그 전에는 무보호.

1) T1 또는 더 시도할 티켓이 없으면 종료 확률에 합산.
2) 보호 시 필요 유지권의 부족분×2+강화1장을 감당할 수 없으면 종료.
3) 부족분을 구매한 뒤 강화1장 소비.
4) 성공 확률 p로 level+1, 유지권 보존.
5) 보호 실패는 level 유지, 필요한 유지권 전량 소비.
6) 무보호 실패는 level<10이면max(0,level-1), level>=10이면0.
7) 같은 상태의 확률을 합산하고 전체 종료 확률 합1을 검증.

정책 B Bellman 값 V(남은티켓, level, 유지권):
- 이미T1이면1, 유효 행동이 없으면0.
- 유지권 구매2장, 무보호 강화1장, 충분한 유지권을 가진 보호 강화1장 중
  성공/실패 후 V의 기대값이 최대인 행동을 선택.
- 미래 RNG를 미리 보지 않는다.
- 현재 규칙에서 한 시도에 최대3개만 필요하므로 같은 가격의 사전 사재기는 추가 이점을 주지 않는다.
- 최고티어 기록이나 랭킹 보존 효용은 이 목적 함수에 들어 있지 않다.

교실 시간 모형:
n=floor(퀴즈배정초/문항당초), C~Binomial(n,정답률), 총티켓=10+2C.
각 가능한 C의 확률에 해당 예산의 도달률을 곱해 합산한다.
정답 수 평균 하나만 대입한 결과와 정확히 같지 않을 수 있다.

부록 C. Codex에 함께 전달할 짧은 실행 지시
======================================================================

YeomBallForge를 이 문서의 우선순위로 업데이트하라.
먼저 현재 브랜치와 사용자 변경, AGENTS.md, 구현 현황을 확인하라.
현재 main이 아직 v1.1이라면 기존 v2의 랭킹·인벤토리·상시 퀴즈·게임필 기반을 먼저 완성하라.
경제는 이번 v2.1의 모든 단계100% 미만, 최종3%, 유지권1/2/3개 규칙을 적용하라.
실패 경계는 현재 티어, 확률과 유지권 필요 수는 목표 티어 기준으로 구현하라.
중간 티어에서도 대표 능력과 보관·상성 선택이 재미있게 작동하도록 하라.
대표8개 기믹의 타격·방어·HUD·원래 구체 외형을 검증한 뒤 전체 프로필에 확대하라.
전술 특성1칸, 정확한 최근 경기, 보상 없는 비교 연습을 실제 시뮬레이션으로 연결하라.
서버 권위, 원자성, 재접속, 출전 스냅샷, 중복 정산 방지를 우선하라.
기존26+신규24 프로필 목표를 외형 수로 채우지 말고 실제 행동 차이로 보고하라.
완료된 것, 검증한 것, 아직 남은 것을 구분하고 재현 가능한 증거를 제출하라.
AWS/Render 운영 연결과 자동 병합/운영 배포는 별도 지시를 받기 전 수행하지 말라.
