### 게임의 최종 감각

강화와 랭킹 보상이 없어도 볼 실험실에서 두 공을 싸움 붙이고 싶어질 정도로 전투 자체를 재미있게 만들어라. 화면은 깔끔한 흰 전장, 명확한 무기와 공의 실루엣, 격투게임처럼 읽히는 상단 HUD를 유지한다. 큰 타격은 묵직하게 맞고 실제로 날아가 벽과 부딪치며, 빠른 연타는 날카롭고 리드미컬해야 한다. 공격 종류마다 고유한 피격 반응과 소리를 갖는다. 의성어 텍스트로 타격감을 대체하지 않는다.

**이번 버전의 핵심: 전투 중 각 공의 고유 기믹이 발전한다.** 단순히 공이 튕기면서 쿨다운마다 스킬을 반복하는 게임이 아니라, 충전·방어·연계·무기 성장·변신 등으로 한 경기 안에서도 기대와 변화가 생긴다. T1은 특별한 고유 각성으로 완성한다. T1을 얻지 못한 학생도 T10~T5에서 자기 공의 핵심 재미를 충분히 경험해야 한다.

### 범위

필수: 기존 50개 프로필의 기믹·연출·밸런스 정비, 전투 중 진화, 합법적인 T1 프로필 전체의 각성, 원본 외형 차별화, 기존 상단 HP HUD 개선, 주목 경기 추천과 기록 기반 하이라이트, 회귀 및 부하 검증.

비범위: 대규모 신규 로스터(20~30종은 v2.3 HERO UNIVERSE), 신규 팀전/보스/PvE, 영구 전투력 성장, 새 뽑기 재화, 강화 확률 재조정, 랭킹 점수 개편, AWS 연결. 신규 공은 이번에 수량을 늘리기 위한 목적으로 추가하지 않는다. 50개 전투 프로필과 508개 합법 티어 폼을 보존한다. 신규 원본 그래픽은 같은 프로필의 시각 품질을 올리는 것이며 신규 전투 프로필로 세지 않는다.

## 3. 전투 진화 시스템 — Battle Evolution

### 3.1 규칙

전투 진화는 **해당 경기 안에서만** 발생하는 공의 고유 행동 변화이다. 강화 티어, 인벤토리, 다음 경기 전투력과 별개다. 공에 맞는 명확한 조건으로 변화를 일으킨다. 모든 공에 공격력 +n% 스택을 일괄 복제하지 않는다.

1. 경기 시작 시 초기 상태 생성. 첫 고유 행동을 볼 수 있게 대기시간과 조건을 조정하되 일반 경기의 시작 위치나 RNG를 조작하지 않는다.
2. 유효 직접타, 무기 접촉, 벽 반사, 유효 방어, 공격 회수, 실제 소환체의 유효 피해, 이동 거리, 과열, 실제 탄환 포획 등 프로필별 조건으로 자원을 쌓는다.
3. 해당 자원이 준비되면 다음 지정 공격/상태가 변화한다. 변화는 기믹별로 물리·범위·크기·발사 패턴·속도·방어·반동·회수 등 실제 판정에 반영한다. 연출만 커지면 안 된다.
4. 소모/냉각/만료 후 회복 구간을 갖는다. 영구적으로 모든 수치가 커지는 구조 금지. 지속형은 최대 2단계, 일시적 burst는 충전 1개를 기본 상한으로 한다. 기믹별 명세가 더 작은 상한이면 그 값을 사용한다.
5. 경기 종료, 재경기, 다음 토너먼트 경기, combined의 럼블 진입 시 상태를 완전히 초기화한다. 재접속은 해당 서버 경기의 현재 상태를 복원한다.

현재 `tacticResource()` 또는 `newResource()` 하나만 선택하여 다른 상태가 가려지는 경로를 확인한다. 고유 기믹, 전술 특성, 진화, 각성은 서로 다른 상태로 표현하되 HUD 과밀을 피한다. 핵심 기믹 게이지 1개를 우선, 특성/상태는 짧은 보조 표시. 같은 조건을 여러 자원에 중복 사용한다면 의도된 경우만 허용하고 수치 합산을 검증한다.

### 3.2 공통 데이터·사건 계약

새 구현은 `packages/content/evolution.js`(후보), `packages/sim/evolution.js`(후보) 등 분리된 모듈로 추가하고 기존 mechanics/tactics/damage 파이프라인에 명시적으로 연결한다. 파일명 자체보다 책임 분리가 중요하다. 콘텐츠 단일 원천에 `profileId`, 트리거 유형, 횟수/윈도우, cap, 발동/소모, recovery, 효과 파라미터, 약점, `awakeningId`, 지원 티어, VFX/SFX ID를 둔다. 설명과 실제 수치는 같은 설정을 읽는다.

전투 상태 예: `evolution: {kind, value, max, stage, ready, activeUntil, recoveryUntil}`. 실제 발동 사건: `evo-charge`, `evo-ready`, `evo-activate`, `evo-consume`, `evo-expire`. T1은 별도 `awakening-ready`, `awakening-start`, `awakening-hit`(해당 시), `awakening-end`. 서버 사건에 `matchId`/tick/seq/eventId/rootAttackId/sourceId/targetId/접촉점/방향/실제 적용값을 연결한다. 이미 있는 필드는 재사용한다. HUD는 snapshot의 현재 상태를 사용하고, 연출은 사건을 한 번만 표시한다.

유효 직접 피해는 실제 HP 감소가 양수이고 적 소유자에게 가한 것이어야 한다. 보호막에 완전히 막힌 공격·무효·사망 대상·압박·연출 이벤트는 직접타 자원으로 세지 않는다. 방어형은 실제 방어량 양수와 방어 사건을 센다. 광역/멀티히트는 하나의 rootAttackId를 한 번만 충전하는 것이 기본이다. 실제 연타를 의도한 프로필은 독립 공격 ID 및 재발동 간격을 사용한다. 지속 피해·반사·소환·파생 피해는 기본적으로 재귀 충전 금지; 명시한 소환형/흡수형만 전용 사건으로 허용하되 root와 소유자별 cap을 둔다. 같은 사건에서 발동이 반복되거나 무한 반사·부활·증폭이 생기지 않게 한다.

전투 RNG와 시각/음향 RNG를 분리한다. 상태 전이와 피해 계산은 고정 tick으로 처리. 프레임레이트, reduced motion, 음소거, 화면 전환, 리플레이 배속은 전투 결과에 영향 없음. 타격 정지를 서버 tick 정지로 구현하지 않는다. 객체 수명·대상 원장·자원 히스토리 모두 상한이 있어야 한다.

### 3.4 수치 가드와 작업 방법

- 초기 권장: 성장형 지속 효과는 원래 대비 최대 10~20% 반경/회전/속도 중 하나를 강화. 두 단계 합산 상한은 기본값의 1.25배 이내부터 검증. 단발 준비형은 기존 해당 공격 계수 1.15~1.35 또는 동등한 변화 중 하나. 반경 증가와 피해 증가·속도 증가를 모두 곱하지 말고 실제 DPS와 방어 효율을 함께 측정한다.
- 강타는 프로필별 impulse와 질량으로 차별화한다. 공통 최대 속도 425를 우선 보존. 튜닝이 필요한 경우 통과 판정과 벽 반사 안정성을 함께 검사한다. 강타 1회의 유효 직접 피해/벽꿍/파생 합계가 일반 풀피를 순식간에 지우지 않는지 확인한다. 권장 초기 검토 기준: 동티어 상대 최대 HP 25% 초과의 단일 root는 반드시 별도 검토(이미 의도된 특수 공격도 기록).
- 경기 중 영구 공격력·이속 스택, 무제한 소환수·탄환·장판·CC, 반사 연쇄, 회복의 회복 등 금지. 기존 전술 특성과 중첩한 최악의 조합을 확인한다.
- 일반 T5 1대1에서 자신의 대표 기믹이 실제 발동하고 관측되는 비율·첫 발동 시간·준비 대비 명중/소모를 기록한다. 6초 준비 시연만으로 일반 경기 품질을 입증하지 않는다. 적 탄환이 있어야만 발동하는 흡수형처럼 의도적 조건부 기믹은 조건 충족/미충족 상황을 나눠 본다.
- 진화는 전투 중 도달하는 장면을 기대하게 만드는 장치지 승자에게만 끝없이 눈덩이를 굴려주는 보상이 아니다. 조건에 따라 지는 쪽도 방어·피격 투지 등 다른 방식의 성취를 얻는다. 모든 공에 역전 보정을 억지로 넣지는 않는다.

## 4. T1 고유 각성 — Mythic Awakening

### 4.1 공통 계약

T1은 v2.1 경제(최종 성공률 3%)를 그대로 두되, 그 희소성에 걸맞은 고유 전투 정체성과 시각적 완성형을 제공한다. 현재의 8종 공통 3초 ×1.12 버프를 그대로 남겨 신규 각성에 곱하지 않는다.

- 실제 T1 폼을 보유해 해당 경기의 고정 출전 스냅샷에 level 19가 존재할 때만 활성화. 폼/프로필 ID도 합법성 검증. T2 이하, 시연용 가짜 레벨, 다운그레이드 공, 상대 능력 복사에서 온라인 각성 불가.
- 각성은 기본적으로 경기당 1회. 자원/고유 행동과 연결된 조건을 만족하면 예고가 나오고, 지정 행동 때 실제 발동한다. 준비 상태/발동/소모/종료를 분리. 예고 중 사망하면 발동하지 않는다. 오래 준비만 하다 끝나는 경우도 기록하고 조건을 검토한다.
- 공통 조건은 **HP 35% 이하**를 모든 공에 강제하지 않는다. 실제 유효 공격·방어·자원 충족을 주 조건으로 삼고, 방어/회복 계열처럼 체력 조건이 정체성에 맞으면 사용한다. 경기당 1회라고 해서 모든 T1이 반드시 발동해야 하는 것은 아니다.
- T1은 공격력 상승뿐 아니라 공격 패턴·도달 경로·무기·효과의 변화가 보여야 한다. 보통 1회 기술 강화 또는 1.5~3초 제한 상태로 끝낸다. 강력한 1회 효과의 별도 피해가 중첩되는지 검사하고, 기존 공격을 대체하는 방향을 기본으로 한다. 공통 상시 무적·전장 전체 확정 피해·상성 무시·무제한 CC 금지.
- 발동 조건과 효과는 상단 HUD, 도감, 선택 카드, 6초 각성 전용 시연에서 확인 가능. 준비된 시연은 명시한다. 기존 50개 일반 능력 시연 유지. 원본 리플레이에도 서버에서 결정한 실제 각성 시점과 효과 상태가 남아야 한다.
- `basic`은 현재 T1에 도달 가능한 폼이 없으므로 각성 비대상이다. 49개 합법 T1 프로필을 카탈로그에서 도출하여 구현 수를 검증한다. 새 합법 프로필이 기준 변경으로 생겼다면 누락 없이 검토한다.

| mimic | 모사 완성 / 허용 복사 유효타 누적 | 허용한 공격 1회 강화 복사, 다른 T1 각성의 복사 금지. 불가 유형에는 일반 기믹으로 싸움. |
| greatsword | 절산검 / 이동 축력 완충 후 베기 | 큰 부채꼴 단발 강타, 긴 예고와 회수, 실제 범위 일치. |
| storm | 천둥의 심판 / 고정 낙뢰 유효타 누적 | 표식이 보이는 마지막 큰 낙뢰, 이전 표식과 중복 피해 상한. |
| current | 대조류 / 흐름 방향 변경 누적 후 새 물길 | 짧은 강한 물길의 방향 전환. 몸체·탄환 경로와 정확히 일치, 벽/무한 강제 이동 금지. |
| decoy | 거울 수호 / 분신의 실제 차단 누적 후 소환 | 제한 내구성의 강화 분신 하나, 실제 표적과 파괴 반응. 추가 생존자/영구 탱킹 없음. |
| mycelium | 균사 만개 / 유효 연결선 횡단 누적 | 최대 3노드의 한 번의 연쇄 파열·짧은 구속. 같은 대상 무한 연쇄 금지. |
| vampire | 적월 흡혈 / 실제 흡혈 누적 후 유효 근접 적중 | 제한된 회복/반격 1회, HP 상한·실제 피해 기준. 사망 후 소생 없음. |
| fracture | 백야 붕괴 / 냉기 표식 완충 후 직접타 | 실제 표식의 한 번의 큰 파쇄, 얼음 결정 비산과 짧은 밀침. 표식 즉시 소모. |
| combo | 천격 마무리 / 독립 직접타 세 번 연계 후 다음 적중 | 실제 발사형 결정타 1회, 긴 회복. 연계 사이 시간 초과 시 준비 만료. |

### 4.3 각성 밸런스

현재 기본 성장 곡선과 속성 배율을 보존한다. 동일 프로필·비슷한 특성·중립 조건에서 T1은 T3/T5보다 유리한 것이 자연스럽지만, 서로 다른 기믹·상성에서 T1이 자동 승리하면 안 된다. 반대로 T1 희소성을 무시하여 T5가 동일 프로필 T1을 평균적으로 압도하지 않게 조사한다. 전투마다 각성 발동률·발동 시간·추가 유효 피해·반격/회복량·발동 후 승률·미발동 사유를 분리해 기록한다. 단순히 승률을 맞추려고 모든 각성의 공격력 숫자를 똑같이 만들지 않는다.

## 5. Game Feel 2차 리워크 — 실제 물리와 표현의 결합

### 5.1 현재 구현을 개선할 위치

`packages/sim/arena.js`, `packages/sim/mechanics.js`, `packages/sim/tactics.js`, `public/arena.js`, `public/presentation.js`, `public/game-audio.js`, `public/combat-hud.js`, `public/orb-materials.js`를 우선 조사한다. v2.1에 분리 넉백·HP trail·합성음·표시 상한이 있으므로 그 구조를 활용한다. 겉보기로 화면을 크게 흔드는 것만 개선으로 간주하지 않는다.

공격 파이프라인:
실제 예고 → 실제 공격/무기 이동 → swept hit → 방어/회피/유효 피해 확정 → 피격 압축/방향 스파크 → 짧은 표시용 hit-stop → 실제 충격량/이동 → 벽 충돌(해당 시) → 실제 후속 피해 → HP HUD → 회복/KO.

서버 hit event에는 최종 적용 피해, 실제 방어량, 충돌 normal, 충격량, source/target, contact position, root ID, tick, `impactKind`와 `impactGrade`를 연결한다. 기존 `nx/ny`, `impulse`, `reasonTags`, `procDepth` 등을 재사용한다. 시각 강도는 공격의 콘셉트, 실제 유효 피해·충격량·속도, 방어/KO 여부에서 계산한다. 단순 화려함이 피해를 거짓으로 전달하면 안 된다.

### 5.2 물리

- 평소 속도와 kx/ky 피격 속도의 분리 유지. 실제 충돌 각도/접근 속도/질량/넉백 저항으로 운동량 배분. 동일 질량/대칭 입력은 위치/ID 처리 순서로 유불리가 달라지지 않게 한다.
- 평상시 약타, 회전 무기, 강한 주먹, 철퇴, 돌진, 폭발의 impulse·감쇠를 차별화. 강타 뒤 너무 빠르게 기본 속도로 되돌아가는 경우 감쇠/회복/안전 상한을 측정해 조절한다. 월드 이동 거리와 시간(피격 후 100/200/350ms), 최대 속도, 벽 반사, 질량별 반응을 전후 비교한다.
- v2.1의 합성 속도 상한 425 및 일반 감쇠 .955는 기본값으로 유지한다. 강타 표현이 부족할 때만 프로필별 impulse/push, 감쇠, 회복을 제한 조절. speedCap 전역 상향이나 모든 공의 속도 상승으로 해결하지 않는다.
- 고속 돌진, 탄환, 큰 회전 무기, 변신 반지름, 순간이동, 복합 넉백에서 tunneling·벽 관통·겹침·NaN·무한 반사 방지. 순간이동은 출발/도착 사이를 전부 타격하는 sweep을 만들지 않는다.
- 벽꿍은 해당 공격이 명시적으로 부여한 wallslam 상태에만 추가 피해. 적중 root당 1회, 실제 유효 벽 접근·충돌 시에만 소비. 일반 반사·밀려서 벽에 붙은 상태·반복 벽 접촉에서 지속 추가 피해 금지. 공격자 소유·만료·동시 충격 우선순위가 결정적이어야 한다.
- 벽의 균열/파편은 기본적으로 장식이며 실제 지형을 파괴하지 않는다. 일반 반사의 작은 벽 반응과 큰 강타로 인한 충돌 표현 구분. 다른 공격의 본래 특성을 의도 없이 벽꿍으로 바꾸지 않는다.

### 5.3 공격 강도별 시작 튜닝안

아래는 렌더러 표시용 초기값(월드·시각 단위 혼동 금지)이다. 서버 판정 정지를 의미하지 않는다. 실제 디스플레이에서 A/B 비교해 조정한다. 모든 효과에 개별 적용하지 않고 서버가 확인한 attack category를 사용한다.

| 종류 | 표시 hit-stop | 카메라 반응(960px 기준) | 변형·사운드·물리 |
|---|---:|---:|---|
| 일반 몸체 약타 | 0~20ms | 0~1px | 작은 눌림/탄성, 짧은 낮은 클릭, 작은 밀침 |
| 연속 검/톱/독침 | 0~16ms | 0~1px | 짧은 방향성 베기·리듬, 연속 피격 텍스트 합산 가능, 큰 넉백 금지 |
| 일반 유효 스킬 | 20~40ms | 1~3px | 콘셉트에 맞는 발광·짧은 변형·물리 반응 |
| 묵직한 강타/발사 | 45~75ms | 3~6px | 방향 압축/늘어남, 실제 큰 비행, 저음+중고역 접촉음, 0.15~0.35초 잔상 |
| 유효 벽꿍 | 35~60ms | 2~5px | 벽 국소 흔들림/균열/파편, 별도 둔탁한 충돌음, 실제 추가 피해와 HP 연동 |
| 방패/패링 | 15~35ms | 0~2px | 맞은 면에서 방어 링·금속음, 방어량과 실제 반격을 구분 |
| 빙결·독·지속피해 | 기본 0ms | 0px | 서리/독 상태, 파쇄 순간만 강조, 틱마다 화면 흔들림 금지 |
| KO 결정타 | 마지막 접촉 강조 60~90ms | 최대 6px | 마지막 순간을 짧게 잡은 후 원본 기록 기반 하이라이트(아래) |

- 공의 압축/신장은 접촉 방향을 기준으로 예: 약타 .94/1.06, 강타 .78/1.18 정도에서 시작해 120~240ms 내 안정 복원. 이는 렌더 transform이고 실제 충돌 반지름을 바꾸지 않는다. titan처럼 실제 반지름 변경 기믹은 snapshot 수치를 그대로 표시한다.
- hit-stop은 PresentationClock의 화면 재생 계층에서만 제한적으로 적용한다. 한 화면에 중첩 hit-stop을 계속 누적하지 않는다. 예: 1초당 총 120ms, 한 사건 90ms 상한부터 검증. 최신 서버 상태와 지연이 너무 커지면 재생을 부드럽게 따라잡는다. 강한 hit-stop이 무기/HP/효과의 시간축을 분리하지 않게 한다.
- 30인 럼블의 전역 흔들림/정지는 기본 끄거나 극히 제한한다. 국소 강타·벽 반응 중심. 효과 객체 및 음향 동시 재생 상한을 기존보다 무작정 늘리지 않는다.
- 공격 예고, 실제 판정 오브젝트, 위치, 충돌, 상태 표시, HP, 이름은 low에서도 유지. 장식 입자, 잔상 샘플 수, 보조 광원, 글로우를 먼저 줄인다. `prefers-reduced-motion`, 수동 저사양/흔들림 끄기, 음소거 옵션을 유지한다. 화면 전체 고빈도 섬광·과도한 흔들림 금지.

### 5.4 대표 8개 체감 장면: 반드시 실제로 만들고 비교

1. 철퇴(mace): 무기 머리가 커지고, 실제 회전 궤도에서 타격 → 크게 날아가 벽 충돌 → 국소 균열 → 둔탁한 저음. 같은 위치의 비충전 타격과 비교한다.
2. 삼중검(trinity): 각각의 검 회전과 유효 연계가 읽히고 검기 세 방향이 보인다. 연타 리듬과 약타의 차이. 연계가 막혔을 때 준비가 과다 충전되지 않는다.
3. 방패(tide): 정면 유효 방어와 뒤쪽 피격을 다른 표현으로 분리. 저장 게이지와 실제 반격 파동. 피해가 막혔는데 큰 빨간 HP 손실을 표시하면 실패.
4. 파동포(beam): 차지→고정 조준→빔 발사→반동→타격. 빔의 실제 선분/폭과 표시 일치, 회피한 상대에는 피해 없음.
5. 번개(bolt): 예고된 직선 돌진과 잔상, 빗나감과 명중의 차이, 회복 단계. 돌진 중 충격량 합산이 의도된 동작인지 확인.
6. 빙결(frost): 상태 부착→실제 감속→파쇄. 얼음 장식이 실제 감속 상태와 맞아야 하고 지속 슬로우/이중 감속 금지.
7. 소환(summoner): 사역마의 발사·적중·진화 및 만료가 읽힌다. 무조건 유도 명중/근접 접근 방해를 줄일 수 있는지 실제 밸런스 검토.
8. 별빛(star): 실제 탄환 흡수→저장→반환. 흡수로 탄환이 사라지는 사건과 반환 투사체가 명확. 흡수 불가 탄이나 탄환 없는 상황도 시연.

이 8종을 최초 수직 슬라이스로 완성한 다음, 나머지 프로필의 동작·타격·각성 표를 구현한다. 대표만 구현하고 전체 완료라고 보고하지 않는다. 49개 T1 각성 및 50개 일반 프로필을 실제로 테스트한다.

### 5.5 음향 리워크

기존 Web Audio의 단순 oscillator 계층을 유지·확장하거나, 검증된 재생 라이브러리를 좁게 도입한다. 모든 공에 같은 사운드를 재생 속도만 조금 바꿔 사용하는 수준에서 벗어난다.

- 음향 레이어: 저음 충격(짧은 저주파), 중역 접촉/재질(금속·돌·고무·유리), 고역 파열/전기, 비행/휘두름, 벽, 방어, KO. 철퇴는 저음·중역, 검은 스냅과 절단, 방패는 금속성 차단, 물은 탄성 파동, 전기는 빠른 톤, 소환은 소환/탄환/적중 분리.
- 예고/발사/명중/벽꿍/KO 사건의 시간에 맞춰 재생한다. 소리만 들리는 가짜 피해 금지. 루트별 같은 음향 중복 억제, 연속 타격은 최대 빈도·볼륨 상한. 압박 지속 틱은 충돌음 재생 금지.
- 기존 기본 음소거(학생) 유지, 호스트가 선택한 경기만 들림. 모드 전환·관전 변경·숨은 탭·리플레이 종료 시 오디오 owner 해제/노드 정리. 사용자 제스처로 AudioContext 활성화. Web Audio 미지원이면 무음으로 안전하게 동작.
- 마스터/SFX/BGM 분리, 볼륨·클리핑 제한, 동시 음성 시작 4~8개 상한을 측정해 선택한다. 큰 소리 자체를 타격감으로 간주하지 않는다.
- 기존 합성음을 활용한 원본 음향, 또는 이용 조건을 확인한 CC0/허용 자산만 포함. 기존 게임의 상용 음원/애니 대사·OST를 다운로드해 넣지 않는다. 수집한 자산의 출처·라이선스·수정·귀속을 기록한다. 실제 청취하지 못했으면 NOT RUN, 오디오 사건/자동 검사와 청취 평가는 분리 보고.

## 6. 그래픽·전장·HUD — 기존 50종의 시각적 품질

### 6.1 전장과 본체

- 전장 내부는 흰색(#FFFFFF 계열), 진한 사각 테두리. 장식 배경/검은 바닥/시야를 흐리는 패턴을 넣지 않는다. HUD와 외곽 UI는 현 UI 색감을 살리되 전장이 중심이 되도록.
- 공 크기와 표시 좌표는 실제 collision radius와 맞춘다. 본체/장갑, 무기, 방패, 투사체, 소환체는 서로 다른 형태로 명확히 분리. 본체 아래에는 플레이어 이름만. HP바, 티어, 긴 능력 설명, 지속 텍스트를 공에 달지 않는다.
- 기존 `orb` / `portrait` / `hybrid` 선택과 26개 초상화, 금속/발광 구체 재질을 보존한다. 3가지 렌더 모드가 동일한 판정과 동일한 전투 사건을 사용한다. 원본 자산을 지우거나 모든 공을 초상화로 통일하지 않는다.
- 신규 24개 프로필의 기존 portraitKey 별칭을 실제 독립 원본 그래픽으로 교체하는 것이 목표다. 최소 모든 프로필은 전투 실루엣(구체 재질, 문양, 무기, 장식, 색 대비)에서 구분돼야 한다. 50개 ID의 독립 원본 그래픽/별칭 여부를 자산 매니페스트로 출력한다. 24개 원본 초상화는 실제 제작하고 경로/라이선스 확인 후에만 완료로 집계한다. 이미지가 미완성이면 품질 좋은 고유 구체를 기본으로 제공하고 실제 미완성 수를 공개하며 패치를 완전 완료라고 하지 않는다.
- 프로필별 고유 무기 형태 예: mace는 무거운 철퇴 머리·연결부, trinity는 검 세 자루, ring은 화염륜 날, returner는 손에 없을 때 방어 공백이 드러나는 방패, elastic은 신축 주먹, captor는 포획된 탄의 공전, mason은 실제 반사벽, mycelium은 최대 3개 노드와 선, sniper는 조준 장치. 원형 그림 하나 위에 효과만 바꾸는 복제 금지.
- 티어 차이는 재질/링/문양/코어/무기 디테일로 발전시키되 더 큰 이미지가 실제 hitbox라고 착각하게 하지 않는다. T1은 각성 전에도 원본 고유 코어와 고급 장식, 각성 때 실제로 달라지는 무기/상태/오라. 같은 폼은 도감·선택·실험실·전투·리플레이에서 일관되게 렌더.
- 시각 자산은 원본 벡터/SVG/허용 이미지/스프라이트 기반. 애니·만화·영화의 유명 캐릭터에서 착안한 동작을 사용할 수 있지만, 캡처 이미지·원본 캐릭터 로고·상업 음원은 권한이 확인되지 않으면 공개 GitHub Pages에 포함하지 않는다. 출처 문서 및 THIRD_PARTY_NOTICES 갱신.

### 6.2 격투게임형 HUD

1대1 전장 상단 양쪽에 긴 HP바를 배치한다. 기존 v2.1 HUD를 개선하며 좌우 공 이름·플레이어·T티어·속성·대표 능력/전술 특성·진화 상태/각성 상태, 중앙 남은 시간을 읽기 쉽게 표시한다. 데스크톱에서 전장 너비의 좌우 각각 약 42~45%, 충분한 높이(960px 기준 20~28px 시작), 모바일에서 두 줄 또는 축약형으로 표시하되 HP 수치와 상태를 숨기지 않는다. HUD가 전장 안의 공/무기를 가리지 않게 별도 상단 영역을 할당한다.

HP 표시:
- 남은 HP는 파랑(예: #2563EB), 최근 손실은 빨강(#EF4444), 빈칸은 중립 회색. 좌우 방향은 서로 대칭(왼쪽/오른쪽 플레이어의 바가 서로 마주보게). 현재/최대 HP 숫자를 명확히 표시.
- 100→75 피해 시 파랑은 정확히 75, 75~100 빨간 잔상, 약 0.2초 뒤 0.35~0.45초에 걸쳐 75로 줄어 빈칸으로. 실제 서버 HP와 표시용 trail은 분리. 연속 피해 시 이전 잔상과 새 잔상을 자연스럽게 합치고 새 HP를 틀리게 보여주지 않는다. 회복 시 이전 빨간 잔상 잘못 유지하지 않음, 보호막은 별도 테두리/색/숫자, KO는 정확히 0.
- 접촉 표시와 HP 변화는 동일한 PresentationClock 재생 tick을 사용한다. 프레임 수신이 먼저 왔다고 화면에서 맞기 전에 HP가 깎여서는 안 된다. 관전 전환, 리플레이 탐색/배속, 재접속에서는 해당 경기 tick/ID로 trail 초기화.
- 고유 기믹 게이지(차지/검술/열/흡수/계약 등) 1개, 특성은 작은 보조 칩, 각성 준비/발동/소모는 전용 표시. 같은 뜻을 여러 위치에 반복하지 않는다. 숫자/아이콘/짧은 텍스트로 색각 차이에서도 의미 전달.
- 피해 숫자는 실제 접촉점 가까이에 잠깐 보여준다(약타는 작고, 강타는 큰 숫자). 실제 유효 피해량을 표시, 방어/회복/상태는 모양과 부호로 구별. 한 공격의 수치 합산은 원인과 시간을 보존. 의성어/장식 텍스트를 띄우지 않는다. 이름 겹침은 최소화하고, 이름만 몸체 아래에 유지.
- 럼블 호스트의 상단 HUD는 기존 집중 관전 공 중심, 필요 시 선택된 실제 교전 상대 한 명을 추가. 30명의 HP를 전장에 쌓지 않는다. 전체 상태는 옆 목록. 럼블 학생의 개인 카드와 순위·처치자 표시는 유지하며 전장 렌더링을 추가하지 않는다.

### 6.3 강화 표현만 개선

확률·티켓은 유지. 결과→선택 순서는 기존 `lastForge`/`ackForge`와 연결하고, 최소 표시 확인 후 진행하는 현재 원자성을 보존한다. T15~T11 재질·문양 발전, T10 전직, T5 고급 성공, T3 고급 전용 강조, T1 짧고 특별한 입장/각성 코어 공개. 일반 결과를 지나치게 길게 막지 않는다(기존 빠른 연속 조작 보존, 중요한 장면은 약 0.8~1.2초 시작값, 건너뛰기 옵션). 실패/초기화 뒤 즉시 보관 공·퀴즈·재육성으로 복귀. 학교에서 사용하는 게임이므로 숨은 확률 보정, 실패 시 추가 무상 추첨, 과장된 근접 실패 연출, 강제 반복이나 추가 결제를 유도하는 기능은 넣지 않는다.

## 7. 밸런스 리워크 — 실제 경기 기반

### 7.1 우선 조사

v2.1 검증 문서의 사역마 우세 및 59개 극단 조합은 개선 필요 후보이지 결론이 아니다. 현재 공격의 피해/빈도/사거리, 몸체 타격의 유효 접촉, 무기 sweep, 충돌 뒤 거리 유지, 유도탄 명중, 실질 쿨다운, 방어/회복으로 원인을 분리한다.

- summoner 등 소환·원거리: 사역마의 발사 빈도, 유도 강도, 지속시간, 탄수, 실제 접근 방해, 고유 약점이 존재하는지. 무조건 큰 피해 너프부터 하지 않는다. 필요하면 유도 회전 한계, 실제 빗나감, 사역마의 발사 공백 및 근접 접근 창을 조정한다. 소환체 진화 시 개수/피해 중첩 위험 확인.
- 근접: 철퇴/삼중검의 유효 접촉 빈도와 사거리, 몸체 충돌로 무기 머리가 상대를 지나치게 놓치는지, 넉백으로 자기 공격이 방해되는지. 실제 약점을 보완하되 순간이동식 추적, 무한 경직, 전장 전체 무기 금지. 강타/검격/회전 무기는 다른 해결 방식 사용.
- 방어: tide/crystal/returner의 방어각과 공백, 반사/반격 재귀, HP 손실과 block 통계, 방어 공이 환경 압박으로만 승리하는지.
- 기믹이 드문 공: star/captor/mimic 등 조건부 상대와 조건 없는 상대를 구분. 잘못된 유형에 무효 기믹만 계속 시도하며 경기하지 못하는 것은 개선 대상으로 본다. 단순 카운터 정체성을 없애지는 않는다.
- 기존 속성 배율 1.20/0.85와 무속성/공용 처리 유지. 실제 form.element로 계산. 상성/성장 곡선을 바꿔 모든 문제를 덮지 않는다.

### 7.2 자연스러운 경기 종료

현재 30초부터 환경 압박이 적용되므로 40초 제한 0건이라는 결과만으로 전투가 잘 끝난다고 판단하지 않는다. 다음을 별도로 기록한다.

- 압박 시작 전 자연 KO.
- 압박 시작 후 실제 상대 공격 KO.
- 압박에 의한 최종 KO(동일 tick 혼합 피해 포함, 실제 서버 원인 규칙을 기록).
- 무승부/시간 만료/무효.
- 환경 압박 피해 비율, 실제 공격별 피해 비율, 무의미한 몸체 접촉과 기술 발동 실패.

권장 목표: 일반 동일 티어 대전 중앙값 20~35초, 최대 40초 유지, 자연 공격 KO의 비중을 충분히 높인다(압박 자체가 승패 원인인 경기 20% 이하를 초기 검토 목표로 삼되, 방어/회복 의도상 불가피한 조합은 이유를 기록). 압박을 무조건 크게 늘려 제한 시간 기록을 좋게 만들지 않는다. 필요하면 전투 기믹과 판정 효율을 먼저 조정한다. 종료 정책 또는 압박 수치를 변경하려면 전후 결과와 교실 회전율을 보고한다. 럼블 축소/압박 및 기존 종료 규칙은 이번에는 기본 보존한다.

### 7.3 검증 설계와 목표

`tools/combat-v21-analysis.mjs` 및 기존 분석 JSON을 기준으로 재현 가능한 v2.2 분석 스크립트를 추가한다. 기존 표본 재현은 동일한 시드·시작 위치·설정으로 비교한다. 분석용 과거 스크립트에서 `basic`에 T5 같은 실제 불가능 폼을 주는 테스트는 합법 카탈로그 검사로 구분한다. synthetic fixture(강제 초기 상태)는 별도로 표기하고 실제 합법 경기 승률에 포함하지 않는다.

1. **기준 재현**: v2.1 기준과 변경본에 공통 조건을 실행. 최소 기존 816개 케이스를 호환 가능한 방식으로 비교. 수정한 조건은 명시.
2. **전체 동일 티어 스크리닝**: 합법 T5 49개(카탈로그로 확인) 모든 서로 다른 조합, 기본 합법 폼·특성 정책 고정, 최소 8개 서로 다른 시드 × 양쪽 시작 위치 교환 2회. T20/19 기본 공은 실제 해당 티어 및 초반 합법 상대와 별도. 원래 시뮬레이터의 정상 초기화와 다양한 시작 위치/각도를 포함하며 한 가지 위치/속도만 강제 반복하지 않는다.
3. **문제 조합 심층 확인**: 극단 조합/사역마 vs 근접/방어/흡수 등에는 최소 100개 서로 다른 시드 × 좌우 교환(200경기). 공용과 속성, 3개 호환 특성 및 대체 빌드, T1/T3/T5/T10 합법 비교를 위험도 기반으로 추가한다. 모든 49×49×3×3×티어 전체를 단 한 표본으로 검증했다고 주장하지 않는다. 작은 표본과 충분한 표본 구분. 필요 시 시드 목록·Wilson 신뢰구간 제공.
4. **각성 분석**: T1 동일 프로필 vs T3/T5, 서로 다른 계열, 동일 티어, 상성 유불리, 특성 교차. 경기당 각성 횟수, 발동률/시각, 실제 추가 피해/회복/방어/경직, 무효 발동, 강타 root 총 피해를 기록. 원본과 새 규칙을 구분.
5. **럼블**: 근접 다수/소환 다수/장판 다수/흡수 반사 혼합/고급 각성 다수의 최악 시나리오를 30공으로 다회 실행. 정원·객체·rank·처치자·공동 순위·동시 KO·축소·종료·학생 프레임 격리.

밸런스 검토 기준(초기 목표, 자동 숫자 강제 금지):
- 동티어의 다양한 상대에 대한 평균 승률 35~65% 범위 우선 검토. 의도된 카운터는 예외 가능. 충분한 표본의 20% 미만/80% 초과 조합은 원인·대응·개선 여부 공개. 전승/전패를 줄이는 것을 목표로 하되 강한 카운터의 존재 자체를 삭제하지 않는다.
- 동일 프로필 T1 vs T5는 전술·상성이 동일할 때 T1이 유리한 경향(예시 검토 범위 60~80%, 프로필별 근거 필요). 서로 다른 프로필의 T5/T10도 특정 상성/기믹에서 역전 가능. 강한 티어가 낮은 티어를 항상 압도하거나 반대로 티어 자체가 의미 없는 결과는 검토.
- 거울전의 시작 위치/배열 ID/처리 순서 편향을 검사. 동일 입력의 동일 시뮬레이션은 동일 결과. 단순하게 결과를 맞추려고 판정 외부에서 승자를 바꾸지 않는다.
- `win/loss/draw` 분모, 합법 폼 수, 표본 수, 시드, 버전, 시간, 전투 종료 원인, 최대 연계·객체·피해량을 보고. 분석/튜닝 시 실제 학생 수업 데이터를 흉내냈다고 주장하지 않는다.

## 8. 호스트 방송 — FEATURED MATCH

기존 선택 중계를 보존하며 진행 중인 경기 목록에서 **현재 볼 만한 경기**를 추천한다. 학생 개인 화면의 퀴즈/강화/내 경기 동작을 방해하지 않는다. 대규모 방송 스튜디오 UI는 v2.5 범위이며 이번에는 가벼운 추천과 기록 기반 하이라이트를 구현한다.

### 8.1 주목 경기 추천

서버 권위 경기 상태·정산·공개 참가 정보에서만 추천한다. 예시 점수 요소: 상위권 vs 상위권, T1 출전, 실제 히든 출전, 양쪽 HP가 낮은 접전, 직전 수초의 실제 역전(HP 우세 전환), 연승, 실제 고유 각성 직전/발동. 이러한 사실은 근거가 있을 때만 표시. 아직 발생하지 않은 각성을 확정된 것처럼 안내하지 않는다.

- 서버가 경기당 작은 요약 메타데이터를 일정 간격(예: 0.5~1초) 갱신, 이벤트는 별도 bounded 요약으로 업데이트. 최대 3개 추천, 이유 1~2개 표시. 교사가 해당 경기를 선택하면 기존 실제 프레임 구독이 바뀐다. 15개 경기의 전체 snapshot을 동시에 방송하지 않는다.
- 기본 수동 중계. 자동 추천이 매번 송출을 빼앗지 않는다. 자동 전환을 추가한다면 명시적인 선택 옵션, 기본 OFF, 최소 체류 8초, 진행 중 직접 선택/종료 화면/KO 하이라이트 우선. 교사 수동 선택은 즉시 우선권. 경기 종료 후 선택한 확정 결과 유지.
- 같은 추천이 매 tick 바뀌는 문제 방지(히스테리시스·갱신 주기), 기존 버튼 DOM/스크롤/포커스 안정. 학생 Top10 갱신 및 퀴즈 답안 포커스가 추천 이벤트 때문에 초기화되지 않아야 한다.
- 화면: 상단 선수 HUD, 흰 전장, 측면 Top10, 진행 중 경기 요약, 남은 시간. 작은 화면에서는 세로 배치. 학생 화면에는 자기 경기 자동 관전 우선권을 유지하며 다른 학생의 개인 정보/문제/지갑을 추가 공개하지 않는다.

### 8.2 기록 기반 하이라이트

실제 전투 사건으로 마지막 3~5초의 KO, 큰 wallslam, 방패 반격, 고유 각성, 실제 HP 우세 역전 등의 후보를 생성한다. rootAttackId와 eventId, tick 범위, 원본 matchId로 참조한다. 과장된 자동 문구를 만들지 않는다. 예시: `철퇴 강타 → 벽 충돌`, `T1 각성 적중`, `남은 HP 8%에서 역전`(실제 사건이 있을 때만).

- 최근 3경기 원본 기록 재생 기능을 확장한다. 하이라이트는 기존 원본 archive의 tick 범위만 재생하고 새 전체 기록을 복제하지 않는다. 이미 해제된 archive는 재생 불가를 표시한다. 기존 2MiB 원자료/64MiB 압축 아카이브/90개 참조+교사 선택 한도 및 경기 예약 공간 정책 유지, 더 큰 메모리 예산을 무단 확대하지 않는다.
- 결정타 슬로모션은 원본 기록의 마지막 구간에서 .5~.75배 정도로 선택 재생. 실시간 전투에서는 표시용 제한 강조만 허용. 판정·수업 시계·다른 경기·랭킹 정산을 멈추지 않는다. 자동 하이라이트는 교사 선택 옵션 또는 결과에서 클릭하는 방식, 재매칭을 막지 않는다.
- 재생/탐색/배속/관전 변경/닫기/재접속에서 이벤트가 중복 재생되지 않고 오디오 owner와 RAF 정리. 실제 원본 해시·버전 검사 유지. 새 규칙과 호환되지 않는 오래된 기록은 원본 재생 가능 범위를 명시하거나 불가 표시한다(새 규칙으로 승패를 재계산해 원본처럼 보여주지 않음).
- T1 도달/히든 해금 공지: 서버가 합법적으로 확정한 결과에 한해서 수업당 동일 학생/슬롯의 동일 성취 알림을 중복 없이 짧게 노출. T1이 드물게 등장했다는 정보 제공이며 모든 학생의 강화 실패/하락을 공개하지 않는다. 이름과 공, 티어 외 지갑/정답수 등 비공개 정보 금지. 알림 끄기 가능, 교사 송출/퀴즈/강화 진행을 가로막지 않는다.

### 10.2 성능 목표

기존 전역 투사체 120, 필드 30, 공당 기본 투사체 6, 필드 3, 표시 사건 링 128 및 실제 기록 수집 원리를 보존한다. 각성/진화도 이 한도를 지킨다. 30인 럼블에서 각성 30개가 같은 tick에 발생하는 최악 상황, 소환/반사/분신/장판, 15경기 병렬, 리플레이 조회 중 퀴즈/강화·재접속을 측정한다.

- 렌더 객체·파티클 풀/캐시·음향 노드·이벤트 처리·HUD 갱신을 bounded하게. 동일 프레임에 캐릭터 스프라이트를 매번 새로 생성하지 않음. Canvas 텍스트/스프라이트 캐싱, visibility/viewport/DPR 관리. 필요 시 고유 무기 그림도 캐시. 장식 이펙트 풀의 최소/최대 상한은 실제 비교로 정하고 문서화.
- 고정 60Hz 시뮬레이터와 표시 갱신을 분리. 서버 시뮬레이션 뒤처짐/대기열 backpressure를 감추지 않는다. 전투 결과·이벤트·HP는 실제 서버 상태에서 전달하고 브라우저가 독립 승패 계산하지 않는다(명시적 오프라인 연습 제외).
- 정상 부하 비교의 초기 목표: 동일 장비/동일 테스트 조건에서 v2.1 대비 응답 P95, tick 배치 P95, CPU·메모리, 최대 패킷, 렌더 CPU P95가 큰 폭 악화되지 않음(20% 이상 악화는 원인과 개선 여부 필수 보고; 장비/측정 조건이 다르면 직접 비교하지 않음). 개발 환경에서 15동시 경기의 서버 tick 배치 P95 4ms 이내를 후보 목표로 삼되 보장하지 않음. 짧은 부하뿐 아니라 최소 15분 실제 벽시계 soak(가능하면 30분)으로 안정성 확인. 가속 시뮬레이션은 별도 처리량 지표.
- 실제 실물 기기에서 테스트하지 못했다면 60FPS를 보장하지 않는다. 최소 390×844, 844×390, 1024×768, 1440×900, 1920×1080에서 화면/버튼/전장/HUD/랭킹 가독성과 수평 넘침 검사. Android/iOS·Safari/Firefox 등 가용 환경에서 구분 보고. 프레임이 낮아도 실제 투사체/무기/충돌 판정 및 HP 유지.
- 렌더 품질 저하 정책: 파티클/글로우/잔상/음성 수 → 카메라 흔들림/보조 장식. 판정 오브젝트·예고·피격·HUD·이름은 유지. 학생 기기마다 다른 승패가 생겨서는 안 된다.

## 11. 구현 순서와 품질 게이트

이번 작업은 한 번에 수백 개의 이름/수치만 바꾸는 작업이 아니다. 기존 저장소의 테스트/작업 규칙을 따라 다음 게이트로 진행한다. 각 게이트에서 실제 구현과 검증을 남기고 다음 단계에 진행한다. 시간/도구 제약으로 일부만 구현했다면 남은 범위를 솔직하게 보고한다.

### A. 기준선/대표 전투 수직 슬라이스

- 현재 main 코드와 기존 102 테스트를 실행해 출발점 확인. 실제 환경 제약이면 구분 보고. 기존 대표 8종의 실제 정상 전투·준비 시연의 event, impulse, HP, 사운드, 그래픽을 저장.
- 진화/각성/표현의 공통 계약과 상태·사건 경계 구현. 대표 8종부터 진화와 T1 고유 각성, 무기와 hit-stop, HP trail 동기화, 실제 강타/벽꿍, 음향을 완성.
- v2.1 대비 동일 시드/조건 before/after 영상 또는 프레임 시퀀스와 계측(피격 이동 거리, 발동 조건, 피해, 벽 충돌)을 제출. 영상 캡처가 불가능하면 원본 상태·이벤트 및 여러 시점 화면으로 대체하고 청취/동영상 미검증을 명시. 스크린샷 하나로 타격감 검증했다고 주장하지 않는다.

### B. 전체 프로필 확장

- 50종의 진화와 49종 합법 T1 각성 매니페스트를 완성. 기존 진화/특성 중복 효과 정리, 프로필별 발동 조건/약점·수치/표현 일치.
- 신규 24종 독립 그래픽 제작 및 50종 구체/혼합/초상화 렌더 일관성. 원본 구체형 유지. 고유 무기와 상태/각성 자산, 강화 표현 개선. 모든 프로필의 일반 시연과 각성 시연(가능한 T1만) 제공. 카탈로그/수업 팩/특성 후보/도감 검사.

### C. 밸런스/관전

## 12. 필수 테스트 체크리스트

### 12.1 콘텐츠 및 경제 회귀

- 50개 `CLASSES` 각각 정확히 하나의 일반 진화 정의, 508개 합법 폼 보존(최신 기준이 바뀌면 원인/수량 보고). T1 합법 프로필 도출 및 전체 고유 각성 정의, basic T1 생성 거절. 3개 호환 특성, 팩별 후보와 경로·공용/히든 처리 유지.
- 기존 v2.1 확률표/실패/유지권/보상/원장 및 정확 DP와 Fraction 교차 검산 동일. 슬롯·공유 지갑·보관 잠금·강화 결과/선택 순서와 재접속, 중복 commandId 처리 유지.
- `npm test` 기존 assertion을 삭제/약화하지 않는다. 새 경제를 만들지 않았으므로 경제 테스트 기대값을 고쳐서 통과시키지 않는다. 전투 규칙이 실제 변경된 기존 수치 기대값은 근거와 새 assertion을 설명한다.

### 12.2 전투 기능

- 50종 대표 일반 진화의 실제 트리거/미충족/만료/회복/소모/다음 경기 초기화. 조건별 양수 피해/방어량/유효 반사/소환/이동 거리 원장 검증.
- 49종 T1 각성의 합법 폼과 실제 특수 공격/방어/변화. 발동 준비만으로 PASS 처리 금지. T2 이하, 다운그레이드, 무효 폼, 재접속, 동일 root 중복, 사망, 동시 KO, 복사, 다음 경기 초기화. rewind/phoenix 1회 한도 특히 검증.
- 기존 10특성 및 프로필별 3후보와 새 진화/각성의 중첩, 무한 반사·소환·CC·지속 피해·회복·벽꿍 없음. 모든 유효 결과에서 HP·좌표·각도·속도 유한, 범위/수명/개수 상한.
- actual contact→event→damage→HP→KO의 단일 판정 경로. 각성/변신의 표시와 hitbox 일치, 빨라진 회전/무기의 swept 경로. 대상 없는 순간이동/고속/벽/겹침 fixture와 정상 경기. ID/배열 순서/좌우 교환의 편향.
- 환경 압박·타임아웃·공동 탈락·순위·처치 원인, 모든 기존 모드 승패 처리 정상.

### 12.3 표시·음향·HUD·리플레이

- 흰 전장, 양측 긴 파랑 HP+빨강 잔상+빈칸, 실제 수치/피해 타임라인, 연속피격/회복/방어/KO/리플레이 탐색/관전 전환. 공 아래 이름만. 30인 럼블은 집중 대상 HUD와 전체 목록, 학생은 개인 카드만.
- 약타/연타/강타/벽꿍/방어/빙결/소환의 서로 다른 연출과 음향 사건. 낮은 그래픽·모션 감소·음소거 상태에서 동일 seed/hash/outcome. hit-stop이나 느린 화면이 서버 시계나 다른 경기를 바꾸지 않음.
- 그래픽 모드 전환 후 자산 누락/실루엣/판정, 모든 50종 아이콘/초상화/구체, 일반 시연/각성 시연/도감/강화 카드. 실제 원본 24개 제작 여부 별도 집계.
- 주목 경기 추천의 근거·권한·갱신 빈도·수동 선택 우선·종료 결과 유지. 학생에게 불필요한 다른 경기 좌표/개인 정보 없음. 하이라이트 원본 무결성/해제·최근3경기 한도·점수/재화 불변, 늦은 요청/닫기 이후 재등장 방지, RAF/음향 owner 정리.
- T1 공지 중복·수업 시간/답안 포커스/강화 결과 보호. 강제 팝업, 과장된 승리/실패 메시지 없음.

### 12.4 부하·환경

- 기존 테스트와 빌드, `git diff --check`, 브라우저 콘솔 오류, 정적 하위 경로/빌드 자산 검증. v2.1 기존 스크립트와 새 v2.2 검증 스크립트 활용.
- 동일 조건의 기준/후속 부하 수치(서버 tick batch/CPU/RSS/heap, ack P50/P95, rAF/render CPU, payload, archive 크기, GC/객체 최대, 음향 node 최대). 31소켓, 15경기, 30공 럼블, 장시간 정상 벽시계와 가속 시뮬레이션 구분.
- 개발 PC 실제 브라우저와 실제 기기의 구분. 청취·실제 모바일 터치·Safari/Firefox·교실 Wi-Fi·AWS 테스트가 불가하면 NOT RUN. 공개 실시간 서버 연결 성공을 주장하지 않는다.

### 최종 합격 기준

서로 다른 공이 단순히 다른 색으로 같은 충돌을 반복하지 않고, 경기 중 자기만의 조건을 달성해 기술이 발전한다. T1은 실제로 얻었을 때 그 공만의 각성과 액션을 보여주며, 중간 티어도 핵심 재미를 갖는다. 철퇴가 때리면 묵직하게 날아가고, 검은 빠르게 베고, 방패는 충격을 받아내며, 소환·흡수·빙결은 각각 이유가 읽힌다. 흰 전장, 이름만 공 아래, 상단 파란 HP/빨간 잔상, 원본 구체 그래픽과 독립된 캐릭터 실루엣이 선명하다. 강화·퀴즈·랭킹·인벤토리·관전·리플레이·멀티플레이는 안정적으로 기존 기능을 수행한다.

**단순히 프로필 수, 이펙트 수, 파티클 수, 테스트 개수를 늘리는 것으로 완료하지 말라. 실제로 플레이어가 공을 골라 서로 싸움을 붙였을 때 어떤 기믹이 작동했고 왜 이기거나 졌는지 느낄 수 있도록 완성하라.**
