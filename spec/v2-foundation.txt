Codex 구현용 통합 명세 / 2026-11-25 / 설계안 v2.0
======================================================================

이 문서는 구현 지시서다. 아래 권장 수치는 첫 구현의 기본값이며, 실측·플레이테스트 후 근거를 남기고 조정한다.
현재 게임에 이미 적용되었다는 뜻이 아니다. 중요한 사용자 요구를 구현 편의 때문에 누락하거나 더미 화면으로 대체하지 않는다.

0. 작업 대상과 실행 범위
----------------------------------------------------------------------

저장소: https://github.com/YEOMT/YeomBallForge
공개 프런트엔드: https://yeomt.github.io/YeomBallForge/
이번 조사 기준 커밋: d6967bc22e8710bb296c47ee65916cbd4fa3ad6d

역할: 시니어 웹 게임 엔지니어이자 게임 디자이너로서 기존 프로젝트를 분석한 뒤 실제 플레이 가능한 v2로 업데이트한다.

- 시작할 때 현재 브랜치·원격·미커밋 변경·AGENTS.md를 확인한다. 위 커밋으로 강제로 되돌리지 않는다.
- 새 작업 브랜치에서 개발하고 기존 작업·사용자 변경을 보존한다.
- Node ES modules + 공통 JavaScript 시뮬레이션 + Canvas2D 구조를 우선 활용한다.
- 현재 엔진 전체를 Unity, Godot, PixiJS 등으로 바꾸는 작업을 기본 해법으로 삼지 않는다.
- 이번 범위는 구현, 로컬/검토 환경 검증, 문서, 검토 가능한 변경 묶음이다.
- AWS 연결은 게임 개발과 검증이 끝난 뒤 별도 진행한다. Render 서비스 생성도 이번 범위에 없다.
- main 자동 병합, GitHub Pages 운영 배포, AWS/DNS/운영 컨테이너 변경은 별도 배포 지시를 받은 뒤 진행한다.
- 새로운 기능은 실제 서버 권위 멀티플레이와 로컬 연습 양쪽에서 작동해야 한다. 서버 배포를 미뤘다는 이유로 멀티플레이 구현·테스트까지 미루지 않는다.
- 기본 제공 외부 API나 유료 생성 서비스를 필수 의존성으로 추가하지 않는다.
- 결과물은 실제 변경 코드, 재현 가능한 테스트, 시연 자료, 규칙·출처 문서다. 계획만 제출하고 구현을 끝냈다고 보고하지 않는다.

1. 이번 업데이트가 해결할 문제
----------------------------------------------------------------------

현재 재미의 병목:
1) 퀴즈와 강화가 한 번 끝나면 다음 선택이 적다.
2) 강화를 망치면 한 판 전체를 포기하기 쉽다.
3) 약타·강타·필살기의 충격과 소리 차이가 작다.
4) 공 근처의 이름·티어·체력바·숫자가 전장을 복잡하게 만든다.
5) 초상화 중심으로 바뀌면서 이전 금속·발광 구체의 매력이 사라졌다.
6) 티어별 이름·색 변화와 실제 고유 기믹 증가가 혼동되기 쉽다.

새 핵심 경험:
“문제를 풀어 재료를 얻는다 → 어느 공에 투자할지 선택한다 → 성공을 확인하고 새 공을 고른다 → 좋은 공을 보관한다 → 출전시켜 전투를 본다 → 순위·상성·패배 원인을 보고 다시 도전한다.”

재미를 만드는 다섯 요소:
- 성장: 정답이 강화권으로 바로 연결된다.
- 선택: 지금 보관할지, 유지권을 쓸지, 다른 공을 만들지 결정한다.
- 발견: 공마다 실제로 다른 능력과 읽을 수 있는 약점이 있다.
- 관전: 한 번의 강타가 접촉·날아감·벽 충돌·HP 변화로 읽힌다.
- 재도전: 패배와 강화 실패 이후에도 다음 행동이 남아 있다.

목표는 제한시간 안의 반복 도전이다. 출석 보상, 현금 결제, 거래, 베팅, 수업 외 무한 접속 보상은 추가하지 않는다.

2. 조사한 현재 코드와 반드시 바꿀 지점
----------------------------------------------------------------------

현재 코드 사실:
- packages/content/economy.js:
  목표 T19~T11은 100%, T10 85%, T9 80%, T8 70%, T7 60%, T6 50%, T5 40%, T4 30%, T3 22%, T2 15%, T1 10%.
- packages/content/forge.js:
  현재 T9~T2에서 실패할 때만 한 단계 하락하고 T10 아래로는 떨어지지 않는다. 초기화는 없다.
- public/session.js에 성공 메시지는 있으나, public/session-screens.js가 pendingChoice를 보고 선택 UI를 함께 렌더링한다. 성공 연출이 먼저라는 순서가 보장되지 않는다.
- apps/server/room.js는 전체 학생이 LOBBY→QUIZ→FORGE→LOCKED/BATTLE→RESULTS를 공유하는 구조다. 학생별 상시 퀴즈·강화·매칭을 넣으려면 방 단계와 학생 활동 상태를 분리해야 한다.
- 현재 볼은 268개 티어별 정의, 기본을 포함한 26개 전투 프로필이다. 268개의 서로 다른 전투 알고리즘은 아니다.
- 현재 public/arena.js는 공 근처에 이름·티어·HP바·HP숫자를 그린다.
- 과거 커밋 23c5c341e5b105c9711635870f53d14895d4921f의 public/arena.js에 skin() 기반 금속·발광 구체 렌더러가 남아 있다.
- 현재 move()는 매 tick 속도를 기본 속도 쪽으로 보정한다. 강한 피격 속도가 빠르게 사라지는 문제를 별도 넉백 상태로 해결한다.

과거 arena.js 전체를 덮어쓰지 않는다. 이전 skin()의 장점을 새로운 외형 모듈로 가져오고 현재의 무기·소환·상태이상·보간 기능을 함께 유지한다.

3. 게임 모드와 수업 흐름
----------------------------------------------------------------------

3.1 새 기본 모드: 랭킹 도전

- 최대 학생 30명 + 호스트 1명.
- 방 참가 후 호스트 시작.
- 기본 제한시간 15분. 호스트가 시작 전 5~30분 범위에서 변경 가능.
- 시작 시 학생별 기본 강화권 10장을 정확히 한 번 지급한다.
- 퀴즈, 강화, 인벤토리, 랭킹전 준비를 학생별로 자유롭게 오갈 수 있다.
- 정답마다 강화권 2장을 즉시 지급한다.
- 참가 중 재접속·공 초기화·새 공 생성으로 기본 10장을 다시 받지 않는다.
- 승패는 자동 시뮬레이션으로 결정한다. 실시간 조작은 없다.
- 같은 학생의 랭킹전은 동시에 하나만 진행한다.

3.2 기존 모드 유지

- 기존 토너먼트와 30인 럼블은 별도 선택 모드로 유지한다.
- 이 두 모드의 결과를 새 랭킹 모드 점수와 섞지 않는다.
- 토너먼트: 학생은 자기 경기를 볼 수 있고, 호스트는 진행 중인 경기 하나를 골라 방송한다.
- 럼블: 전장 렌더링은 호스트만. 학생은 자신의 공 상태, 탈락시킨 상대/사유, 최종 등수를 본다.
- 새 전투 그래픽·HUD·능력은 가능한 한 공통으로 사용한다.
- 새 강화 확률·실패 규칙·유지권·성공 연출·전투/HUD는 세 모드에 공통 적용한다.
- 3슬롯 인벤토리·상시 퀴즈·반복 매칭·Elo는 새 랭킹 모드의 기능이다. 기존 토너먼트/럼블은 한 차례 퀴즈→한 차례 강화→공 한 개 출전 흐름을 유지한다.
- 기존 두 모드의 히든 판정은 단일 출전 공의 세션 최초 T10 도달 1회로 제한한다.

3.3 방 상태와 학생 활동 상태 분리

랭킹 방 상태:
LOBBY → ACTIVE → DRAINING → RESULTS
paused는 별도 상태로 관리한다.

학생의 화면 활동:
QUIZ / FORGE / INVENTORY / WATCH / RESULT
학생의 매칭 상태:
IDLE / QUEUED / IN_MATCH

학생이 QUIZ를 보고 있다고 방 전체가 QUIZ가 되는 구조를 만들지 않는다.
대기열에 있으면서 문제를 풀거나 다른 슬롯 공을 강화할 수 있다.
자기 경기가 시작되면 명확한 알림과 관전 진입을 제공한다. 작성 중 답안·강화 결과 화면을 잃지 않는다.
자동 전투 중에도 다른 공을 강화하거나 문제를 풀 수 있다. 자기 경기로 즉시 돌아갈 수 있어야 한다.

3.4 중도 참가·재접속·일시정지

- 랭킹 ACTIVE 중 참가한 학생도 즉시 자신의 루프에 들어간다. 기존 모드의 다음 판 대기 규칙을 그대로 적용하지 않는다.
- 중도 참가로 종료 시간을 개인별 연장하지 않는다.
- 학생 신원은 서버가 발행한 복구 토큰으로 이어진다. 새 탭·새로고침은 기존 참가자로 복구한다.
- 호스트가 잠시 끊겨도 방을 즉시 삭제하지 않는다. 재접속할 수 있어야 한다.
- 호스트 일시정지는 방 제한시간, 진행 중 경기의 게임 시간, 문제 만료시간, 매칭 대기를 같은 정책으로 멈춘다.
- 일시정지 중 새 보상·강화·대전 시작을 처리하지 않는다.
- 자동 전투 중 학생이 끊겨도 경기는 계속 진행하고 결과를 정확히 한 번 반영한다.

4. 퀴즈: 계속 수급할 수 있지만 중복 지급은 없어야 한다
----------------------------------------------------------------------

- 재화는 플레이어 공통 지갑에 저장하며 세 슬롯이 함께 사용한다.
- 기본 10장 + 유효한 정답마다 2장.
- 랭킹 모드에는 “최대 20문제까지만 지급”이라는 기존 제한을 적용하지 않는다.
- 기본 화면은 5문항 묶음으로 진행 상황을 보여 주되, 한 문항의 정답 보상은 즉시 지급한다.
- 묶음 완료 추가 보상, 승리 강화권, 실패 강화권은 첫 버전에 넣지 않는다. 경제가 정답 수와 연결되도록 한다.
- 오답에는 정답과 짧은 설명을 보여 준다. 같은 attemptId를 고쳐 제출해 보상을 다시 받지 못한다.
- 퀴즈에서 나가도 현재 문항·선택·보상 기록을 보존한다.
- 전투 중 정답을 맞혀도 지갑은 정상 증가한다. 출전 스냅샷 능력치는 변하지 않는다.
- 문항 ID와 문항 버전, attemptId, 발급·응답·채점·지급 상태를 서버에서 관리한다.
- 정답 키를 제출 전 클라이언트 상태에 포함하지 않는다.

반복 문항:
- 아직 풀지 않은 문항을 우선 배정한다.
- 같은 문항의 새로운 보상 가능한 재출제는 마지막 응답 후 90초 이상 경과하고, 다른 문항을 min(4, 전체 문항 수-1)개 거친 뒤 허용한다.
- 문제 순서와 객관식 보기 순서는 섞되 정답 대응을 서버에서 유지한다.
- 후보가 없으면 이미 본 문제의 설명·보상 없는 복습·전투·강화로 이동할 수 있고 다음 보상 가능 시점을 표시한다.
- 작은 문제은행이라도 막힌 버튼만 남기지 않는다.
- 교사 설정에서 문항 수와 예상 반복을 안내한다. 기본 제공 문항과 업로드 문항의 출처·형식을 문서화한다.
- 무작위 클릭 속도로 보상이 폭증하지 않도록 문항당 응답 1회, 발급/제출 빈도 제한을 둔다. 네트워크 지연을 오답으로 처리하지 않는다.

서버 지급 규칙:
- 채점과 지갑 증가는 원자적으로 처리한다.
- 동일 attemptId/commandId 재전송은 같은 결과를 돌려주고 재지급하지 않는다.
- 학생이 클라이언트에서 correct, tickets, answerKey를 보내도 신뢰하지 않는다.
- 보상 내역은 학생 본인과 교사만 볼 수 있다. 공개 Top10에 오답 수를 나열하지 않는다.

5. 인벤토리: 실패해도 다시 출전할 수 있는 기반
----------------------------------------------------------------------

기본 3슬롯:
- 1번 슬롯: T20 기본 공.
- 2·3번 슬롯: 빈 슬롯.
- 빈 슬롯에 T20 공을 만드는 비용은 0장이다.
- 새 T20 공 생성은 추가 강화권 지급이 아니다.

각 공은 독립된 ballInstanceId, ownerId, sessionId, revision을 갖는다.
보관은 복사가 아니다. 강화한 공을 여러 슬롯에 복제하거나 과거 스냅샷을 꺼내 쓰지 않는다.

필수 동작:
- 공 선택, 강화할 공 지정, 출전할 공 지정.
- 보호용 “보관 잠금”을 지원한다. 잠긴 공은 출전 가능하지만 해제 전 강화·교체 불가.
- 슬롯이 가득 차면 교체 대상을 먼저 표시하고 명시적 선택 후 교체한다.
- 강화 대상과 출전 대상은 눈에 띄게 구분한다.
- 전투 패배는 공을 삭제하거나 티어를 낮추지 않는다.
- 대전은 매번 최대 HP에서 시작하며 지속 부상·수리 대기시간은 없다.
- 강화 실패는 현재 강화 중인 공 하나에만 적용한다.
- 다른 슬롯, 남은 강화권, 유지권, 퀴즈 진도, 랭킹 점수는 유지한다.
- 최고 도달 티어는 성취 기록이다. 무료 복원 기능이 아니다.

대기·대전 잠금:
- 준비 버튼을 누를 때 선택한 공의 revision을 검증하고 스냅샷을 만든다.
- 대기열 또는 경기 중인 해당 공은 강화·삭제·교체·외형 변경을 잠근다.
- 다른 슬롯은 자유롭게 사용한다.
- 대기 취소가 서버에서 승인되면 잠금을 푼다.
- 이미 경기로 전환된 뒤 도착한 취소 요청은 경기를 없애지 않는다.
- 결과 정산 후 잠금을 풀고 다시 준비할 수 있게 한다.

첫 안내:
“좋은 공은 한 슬롯에 보관하고, 다른 슬롯의 새 공으로 강화에 도전할 수 있어요.”
T10 이상 무보호 강화 전에는 실제 초기화 결과와 유지권 상태를 같은 화면에 표시한다.
매번 길고 방해되는 확인창을 띄우지 말고, 위험 표시와 선택된 공이 명확한 UI로 설계한다.

6. 강화: 새 확률, 하락, 초기화, 보호
----------------------------------------------------------------------

6.1 티어 정의

T20이 가장 낮고 T1이 가장 높다.
내부 level 0..19를 유지한다면 표시 tier = 20 - level 매핑을 일관되게 사용한다.

확률은 “성공하면 도달하는 목표 티어” 기준이다.
이번 첫 구현 기본값:

현재 → 목표 | 성공률
T20 → T19 | 100%
T19 → T18 | 100%
T18 → T17 | 95%
T17 → T16 | 95%
T16 → T15 | 90%
T15 → T14 | 90%
T14 → T13 | 85%
T13 → T12 | 85%
T12 → T11 | 80%
T11 → T10 | 80%
T10 → T9  | 80%
T9  → T8  | 70%
T8  → T7  | 60%
T7  → T6  | 50%
T6  → T5  | 40%
T5  → T4  | 30%
T4  → T3  | 22%
T3  → T2  | 15%
T2  → T1  | 10%

첫 두 번만 100%로 두어 누구나 T18의 공 선택을 경험하게 한다.
개별 강화 시도 비용은 1장.
확률·비용·실패 결과를 강화 버튼 가까이에 표시한다.
확률은 숨겨진 보정이나 결과 조작 없이 서버 RNG로 판정한다.

6.2 실패 경계: “시도 직전 현재 티어”를 기준으로 확정

- 현재 T20: 실패해도 T20이 바닥. 기본표에서는 첫 시도가 100%라 발생하지 않는다.
- 현재 T19~T11: 실패하면 숫자가 1 큰 티어로 한 단계 하락.
- 현재 T10~T2: 실패하면 그 공을 T20 기본 코어로 초기화.
- 현재 T1: 더 이상 강화 불가.

경계 예시:
- T12 → T11 시도 실패: T13.
- T11 → T10 시도 실패: T12.
- T10 → T9 시도 실패: T20.
- T3 → T2 시도 실패: T20.

사용자의 T10 경계가 겹치는 표현은 위 규칙으로 해석한다. 코드·UI·튜토리얼·테스트가 같은 정의를 사용한다.

초기화:
- 기존 강화 폼이 무너지고 해당 슬롯에 T20 코어가 남는다.
- 해당 공의 티어, 현재 클래스/폼, 전직 방향, 전투 스탯, 현재 히든 클래스, 선택 이력을 초기 상태로 되돌린다.
- 공이 없어져 빈 슬롯만 남거나 다시 시작 비용이 필요한 상태를 만들지 않는다.
- ballInstanceId의 소유권과 감사 이력은 유지하고 revision/generation을 올린다.
- 최고 티어·발견 기록은 성취 기록으로 남겨도 현재 능력에 영향을 주지 않는다.
- 계정 전체·인벤토리 전체 초기화로 구현하지 않는다.

한 단계 하락:
- 해당 티어에서 이전에 선택한 합법적인 공을 복원한다.
- 이력이 없다면 그 티어의 합법적인 기본 후보로 복원한다.
- 상위 티어 스탯·경로 전용 능력이 하위 폼에 남지 않게 한다.

6.3 강화 유지권

- 유지권 1개 가격: 강화권 2장.
- 구매와 사용 의사를 서버에 명시한다.
- 실패로 실제 하락/초기화가 일어날 때만 유지권 1개를 소비하고 시도 전 공을 유지한다.
- 성공하면 유지권을 소비하지 않는다.
- 유지권은 플레이어 지갑에 있으며 적용은 이번 강화 대상에 대해 선택한다.
- 유지권이 없을 때 “유지권 구매 2장 + 강화 1장” 동작을 제공할 수 있다. 총 비용 3장을 표시하고 원자적으로 처리한다.
- 자동 유료 구매를 숨기지 않는다. T10부터 보호를 권장하되 사용자가 선택한다.
- 구매할 돈은 있으나 강화할 1장이 없는 경우 불완전한 원클릭 동작을 하지 않는다.
- 잔여 유지권은 해당 공 초기화나 교체로 사라지지 않는다.
- 유지권을 쓰지 않은 실패는 위 하락/초기화 규칙을 그대로 적용한다.

6.4 성장 방향과 공 선택

- T18부터 각 티어에 최소 2개 선택지를 보장한다.
- T10에 처음 진입하면 성장 방향을 고른다.
- 기존 화염, 물결·빙결, 번개, 대지, 자연, 검술, 공간·별빛, 소환·잔영 방향을 유지·확장한다.
- T10~T1에서는 선택한 방향의 공과 공용 공을 선택할 수 있다.
- 공용 공 선택으로 성장 방향이 사라지지 않는다.
- 새 콘텐츠 추가 후 각 고급 티어에 경로 전용 최소 3개 + 공용 최소 6개가 실제 사용 가능해야 한다.
- 같은 계열을 계속 쓰고 싶은 학생을 위해 현재 계열의 다음 폼을 쉽게 찾게 한다.
- 선택지는 도감 설명만 존재하는 미구현 능력이 아니어야 한다.
- 카드를 고르기 전에 핵심 능력, 발동 조건, 약점, HP/공격력, 외형을 비교할 수 있다.
- 미선택 상태의 공은 다음 강화나 랭킹전 준비를 할 수 없다.

6.5 히든 클래스

- 기본 히든 발견 확률 1%는 유지한다.
- 슬롯별 세션 최초 T10 도달 때 한 번만 판정한다. 3슬롯이면 세션 중 최대 3회다.
- 같은 슬롯을 초기화·삭제·재생성해도 판정 기회를 무한 복구하지 않는다.
- 슬롯별 판정 여부를 공의 전투 초기화 상태와 별도 서버 원장에 기록한다.
- 히든은 별도 고유 기믹·외형을 가진 선택지로 제공한다. 무조건적인 승리권으로 만들지 않는다.
- 현재 공이 초기화되면 그 공의 히든 전투 능력도 사라진다. 도감 발견 기록은 남는다.
- 유지권으로 실패를 막았다면 히든 공은 유지된다.
- 결과·전직·공 선택 흐름 뒤에 히든 제안을 명확히 처리한다. 결과 판정을 연출 중 다시 굴리지 않는다.

7. 강화 결과 연출: 성공 메시지가 반드시 먼저
----------------------------------------------------------------------

필수 UI 순서:
IDLE → REQUEST_PENDING/ROLLING → RESULT_SUCCESS 또는 RESULT_FAILURE
→ 결과 확인 → PATH_CHOICE(필요 시) → BALL_CHOICE(필요 시)
→ HIDDEN_OFFER(필요 시, 수락/거절 확정) → READY

- 서버는 한 번만 티어·재화를 확정한다. 클라이언트는 결과를 단계적으로 보여 준다.
- 성공 즉시 화면 중심에 “강화 성공!”과 T변화를 크게 보여 준다.
- 그 뒤에 성장 방향/공 선택 화면을 연다.
- 공 선택 카드가 성공 메시지 뒤 배경에 미리 클릭 가능하게 나타나면 실패 구현이다.
- 일반 성공 연출 약 600~800ms, T10 전직·고급 도달은 약 1,000~1,200ms를 시작값으로 한다.
- 300ms 이후 “공 고르기” 또는 “계속”으로 빠르게 넘길 수 있게 한다. 문구는 한 번은 읽을 수 있어야 한다.
- 모션 줄임에서는 움직임을 줄여도 성공 문구와 순서를 유지한다.
- 실패는 “강화 실패”, T변화, 유지권 발동 여부를 먼저 보여 준다.
- 초기화는 기존 폼 붕괴→T20 코어 재생으로 짧고 명확하게 표시한다.
- 무한 롤링, 서버 결과와 다른 가짜 확률 애니메이션, 조롱하는 실패 문구를 넣지 않는다.
- 성공 후 공을 고르면 선택한 공의 핵심 능력을 짧게 미리보기 한다.

일관성:
- resultId/commandId로 처리한다.
- 중복 클릭·응답 지연·재접속으로 티켓이 두 번 소모되거나 결과가 다시 추첨되면 안 된다.
- 성공 결과만 받은 뒤 연결이 끊겨도 재접속 후 해당 결과 확인→남은 선택을 이어간다.
- 결과 확인은 표현 단계이며 서버 판정을 되돌리는 승인 단계가 아니다.
- 히든 제안이 남아 있으면 랭킹전 준비를 막고 수락/거절을 먼저 선택하게 한다. 대기열 잠금 이후 히든 수락으로 공을 바꾸지 않는다.
- 종료 시까지 미응답인 히든 제안은 거절로 확정한다.

8. 랭킹 점수, 랜덤 매칭, 경기 정산
----------------------------------------------------------------------

8.1 랭킹은 학생 단위

- 학생 한 명당 방 단위 점수 하나. 시작 점수 1000.
- 공을 바꾸거나 초기화해도 점수는 유지한다.
- 현재 점수로 순위를 계산하고 개인 최고 점수는 별도로 보여 준다.
- 퀴즈 정답 수·티어를 랭킹 점수에 직접 더하지 않는다.
- 봇전·로컬 연습·볼 실험실은 랭킹 점수 0.
- 연승 추가 승점과 반복 패배 강화권을 넣지 않는다.
- “조작 실력” 지표라고 설명하지 않는다. 공 선택과 강화, 상성, 자동 전투 결과를 포함한 수업 내 점수다.

Elo 기본식, K=32:
E_A = 1 / (1 + 10 ^ ((R_B - R_A) / 400))
delta = round(32 × (S_A - E_A))
A의 새 점수 = R_A + delta
B의 새 점수 = R_B - delta

S_A: 승리 1, 무승부 0.5, 패배 0.
R_A와 R_B는 매칭 확정 시 저장한다.
정수 delta 하나를 계산해 대칭 적용한다.
같은 점수끼리 승부가 나면 승자 +16 / 패자 -16.
무승부도 공식대로 적용하며 같은 점수라면 0.
첫 경기부터 점수 변화를 표시한다.
한 번도 경기하지 않은 학생은 “준비 중”으로 따로 표시하고 Top10 성적표에 경기한 학생보다 위로 올리지 않는다.

동점 표시:
점수 → 승수 → 승률 → 같은 조건이면 공동순위.
동점군 내부 표시 순서는 안정적으로 유지한다.
서로 다른 학생을 동시에 임의의 단독 1위로 표시하지 않는다.
Top10은 최대 10개 행이며 경계 동점은 공동순위 설명을 제공한다.
정렬 규칙을 UI 도움말과 테스트에 명시한다.

8.2 랜덤 매칭

- “랭킹전 준비”를 누른 학생끼리 자동 1:1 매칭한다.
- 최장 대기 참가자를 우선 처리한다.
- 다른 후보가 있으면 직전 상대를 피한다.
- 점수 차이와 현재 볼 전력 차이가 작을수록 상대 후보 가중치를 높인다.
- 티어별 별도 리그로 30명을 잘게 쪼개지 않는다.
- 대기 15초 이후 점수·전력 가중치를 완화한다.
- 최근 상대 회피와 전력 차이는 소프트 조건이다. 다른 후보가 없으면 대전을 시작할 수 있어야 한다.
- 후보를 전력순으로 고정 배정하지 않는다. 실제 랜덤성이 있어야 한다.
- 가중치 함수는 데이터/상수로 분리하고 결정론적 테스트용 RNG를 주입한다.
- 같은 학생 자기 자신, 동일 세션 중복 참가자, 대전 중 학생을 매칭하지 않는다.
- 대기시간·현재 상태·준비 취소를 표시한다.
- 상대가 없으면 문제 풀기·다른 공 강화·명확히 비랭킹인 연습전을 제공한다.
- 봇을 실제 학생처럼 숨겨 매칭하지 않는다.
- 승패 조작 담합을 완전히 막았다고 주장하지 않는다. 교사가 반복 대전 이력을 볼 수 있게 한다.

전력 추정:
- 단순히 낮은 티어 숫자만으로 추정하지 말고 실제 HP·공격·능력 프로필과 밸런스 시뮬레이션을 활용한다.
- 숨겨진 전력 값은 매칭 보조용이며 랭킹 점수 자체를 대체하지 않는다.
- 과도한 전력 차이의 경기 빈도를 기록해 조정한다.

8.3 경기 길이와 승패

- 랭킹 1:1은 20~35초 내 결말이 많이 나오도록 조정한다.
- 최대 경기 게임 시간 40초. 호스트 일시정지 시간은 제외한다.
- 30초부터 서버가 동일 규칙으로 압박을 강화해 장기전을 줄인다.
- 40초 종료 시 생존 여부, 남은 HP 비율, 실제 가한 유효 피해 순으로 판정한다.
- 이 값까지 같거나 같은 tick에 상호 KO가 발생한 완전 동률은 무승부를 허용한다.
- 랜덤하게 승자를 만들어 내지 않는다.
- 기존 arena.finish의 강제 승자/seed 동점 처리를 랭킹에 그대로 쓰지 않는다. createArena의 outcomePolicy 등을 통해 랭킹의 무승부와 토너먼트의 진출자 확정을 분리한다.
- 룰은 모든 학생에게 동일하고 전투 시작 전 확인 가능해야 한다.
- 결과에는 승패, 점수 변화, 상대 이름/공, 결정적 피격이나 카운터 한 줄을 표시한다.
- 한 줄 설명은 실제 전투 이벤트로 생성한다. 고정된 가짜 전술 조언을 내지 않는다.
- 결과를 닫으면 “같은 공으로 재도전 / 다른 공 선택 / 퀴즈 / 강화”가 바로 보인다.
- 자동으로 무한 재입장하지 않는다. 재도전 버튼을 명확하게 제공한다.

8.4 동시 경기와 정산

- 30명 기준 최대 15개 동시 1:1을 지원하는 스케줄러를 목표로 한다.
- 기존 토너먼트의 4개 동시 제한을 새 랭킹 모드에 그대로 재사용하지 않는다.
- 실제 동시 한도는 설정으로 분리한다. 15개를 기본값으로 내보내기 전에 부하 검증한다.
- 성능상 한도를 낮춘 경우 실제 한도와 대기시간을 보고하고, “15개 검증 완료”라고 쓰지 않는다.
- 한 학생에게 한 경기만 배정하므로 병렬 승점 갱신 충돌을 막는다.
- matchId별 결과 반영은 정확히 한 번.
- 한 경기의 두 점수 변경과 랭킹 버전 증가는 하나의 원자적 정산으로 처리한다.
- 결과 메시지 중복 전달은 가능하지만 중복 승점은 불가.
- 온라인 랭킹은 클라이언트가 보내는 승패·시간·피해량을 신뢰하지 않는다.

9. 호스트·플레이어 화면과 수업 종료
----------------------------------------------------------------------

9.1 호스트

- 큰 경기 화면 + Top10 + 남은 수업시간 + 진행 중 경기 목록.
- 경기 하나를 선택하면 실제 그 경기를 방송한다.
- 선택한 경기가 끝나면 결과를 짧게 보여 준 뒤 다른 진행 경기로 넘어간다.
- 자동 관전은 서로의 능력이 잘 보이는 경기, 접전, 상위권 대결을 고를 수 있다. 짧은 간격으로 무작정 바꾸지 않는다.
- 진행 경기 없는 동안 Top10과 도전 현황을 보여 준다.
- 학생별 보상/응답·연결·매칭 상태는 교사용 보조 화면에서 확인한다.
- 서버 재시작·시스템 관리 같은 구현 세부사항을 학생 UI에 노출하지 않는다.

9.2 학생

- 남은 시간, 강화권/유지권, 내 현재 순위·점수·개인 최고 점수.
- 퀴즈 / 강화 / 인벤토리 / 내 경기로 바로 이동.
- Top10 표는 학생 화면에도 실제 동일 랭킹 데이터로 표시.
- Top10 밖 학생은 별도 “내 순위” 행을 고정한다.
- PC에서는 Top10을 옆에 두고, 모바일에서는 주요 화면 아래의 바로 접근 가능한 영역에 전체 10행을 제공한다. 숨은 메뉴 안에만 넣지 않는다.
- 랭킹 갱신으로 읽던 퀴즈·카드·스크롤 위치를 초기화하지 않는다.
- 내 경기와 방송 경기를 혼동하지 않게 라벨을 구분한다.

9.3 종료

- 서버의 방 논리시간이 종료 시각에 도달하면 ACTIVE→DRAINING.
- 새 답안 보상, 새 강화 시도, 새 대전 매칭을 받지 않는다.
- 큐에만 있던 학생은 해제한다. 대기만 했다는 이유로 패배 처리하지 않는다.
- 종료 전에 승인한 강화 결과는 유지한다. 결과 확인과 이미 열린 합법적 공 선택은 DRAINING 중 마칠 수 있다.
- DRAINING 종료 시 미응답 선택은 명시된 합법적 기본 후보로 확정한다. 새 강화는 하지 않는다.
- 이미 시작한 경기는 최대 남은 경기 시간 내 완료한다. DRAINING 시작 후 일시정지를 제외한 방 논리시간 45초 안에 정산한다.
- DRAINING 중에도 호스트 일시정지는 허용하며 해당 시간은 경기와 종료 유예에 함께 반영한다.
- 일시정지 없이 45초가 지났는데 미완료인 경기는 무효 처리하고 이미 정산된 경기만으로 종료한다. 서버 정지 후 복귀 시 오래된 tick을 무한 따라잡느라 종료가 막히지 않게 한다.
- 모든 경기 정산 후 최종 순위를 확정한다.
- 호스트가 강제로 즉시 종료하면 아직 끝나지 않은 경기는 무효 처리하고 이미 정산된 경기만 유지한다.
- 최종 화면: Top10, 본인 순위, 개인 최고 점수, 최고 도달 티어, 실제 보유 공, 정답 수, 대전 전적.
- 성적 1위 외 “가장 많이 오른 순위”, “다양한 공으로 도전” 같은 별도 성취를 제시하되 랭킹 점수로 환산하지 않는다.


10. 전투 Game Feel: 한 번의 강타가 읽히게 만들기
----------------------------------------------------------------------

10.1 반드시 구현할 타격 흐름

강한 공격의 예:
공격 예고 → 무기/공이 접근 → 실제 접촉점에 섬광·스파크
→ 맞은 공이 눌림 + 짧은 타격 정지 표현
→ 실제 넉백으로 날아감 + 방향성 잔상/바람
→ 벽에 부딪히면 벽 반응·파편·둔탁한 2차 소리
→ 상단 HP 파랑 감소·빨강 피해 잔상
→ 능력 고유 후속 효과 또는 KO.

“꿍”, “꽝”, “쾅” 같은 글자를 화면에 띄워 타격감을 대신하지 않는다.
피해 숫자·능력 이름·강화 성공 문구는 별도의 정보 표시로 사용할 수 있다.

10.2 공격별 impactProfile

전역 넉백 한 값으로 모든 캐릭터를 같게 만들지 않는다.
최소 다음 프로필을 데이터로 분리한다:

- light: 몸체 약타, 연타, 작은 탄환.
- slash: 날카로운 베기, 짧은 방향성 궤적, 낮은 밀침.
- heavy: 둔기·돌격, 깊은 소리, 강한 밀침.
- launch: 대포·상향 강타, 길게 날아가며 벽 충돌 연계.
- beam: 충전→직선 방출, 지속/최종 타격을 구별.
- pierce: 관통선과 접촉점 강조, 짧은 잔상.
- guard/parry: 방어면의 반짝임·금속음, 피해 차단량 표시.
- element/status: 화염·빙결·번개·독·중력 고유 표현.
- wallImpact: 일반 반사와 강제로 밀려난 벽 충돌을 구별.
- finisher/KO: 한 번의 강조, 이후 전장 정리.

초기 조정값 — 검증 후 조정 가능한 목표이며 검증 완료 수치가 아님:

프로필 | 렌더 타격 정지 | 변형/복원 | 피격 속도 유지·감쇠 | 카메라
약타   | 0~20ms       | 80~120ms  | 짧고 약하게        | 없음 또는 1~2px
강타   | 40~60ms      | 100~180ms | 약 180~250ms       | 3~6px, 80~140ms
발사   | 60~80ms      | 120~200ms | 약 220~320ms       | 5~8px, 120~180ms
KO     | 최대 100ms   | 별도 마무리| 전투 판정은 확정    | 경기당 결정타 1회

픽셀 값은 약 600px 전장 표시 폭 기준이다. 전장 크기에 비례해 조정하고 상한을 둔다.
호스트·학생 HUD와 Top10에는 흔들림·줌을 적용하지 않는다.
일반 벽 반사와 지속 피해마다 대형 흔들림을 재생하지 않는다.

10.3 실제 넉백과 렌더링 변형 분리

시뮬레이션:
- 평상시 이동 속도와 피격 충격량/knockback velocity를 분리한다.
- 충격량은 공격 방향, mass, knockbackResistance, 스킬 계수로 계산한다.
- 피격 직후 기본 속도 정규화로 강한 발사 속도를 바로 지워 버리지 않는다.
- 넉백 속도는 제한 시간 동안 유지·감쇠시키고 최종 속도 상한을 둔다.
- 강한 경직은 최대 누적 시간과 재적용 간격을 둬 무한 경직을 방지한다.
- 대포와 망치는 멀리 밀어내고, 검 연타와 독은 상대를 매번 멀리 날려 보내지 않는다.
- 무거운 공은 같은 공격에도 덜 날아가되 방어/이동의 대가를 가진다.
- 단순 벽 반사는 기본 이동이다. 추가 피해는 wallSlam 가능 능력에만 부여한다.
- 공격별 attackId + 대상별 벽 충돌 소비 플래그로 한 번의 발사에서 무한 벽 피해가 나오지 않게 한다.
- 속도 상한을 높인 경우 기존 “한 tick 이동거리 < 공 지름” 가정을 재검증한다.
- 고속 몸체·벽·무기·투사체의 swept collision 또는 필요한 substep을 구현해 관통과 모서리 탈출을 막는다.
- 실제 hitbox가 없는 큰 이펙트로 피해를 준 것처럼 속이지 않는다.

클라이언트:
- squash/stretch, 스핀, 잔상, 스파크는 표시용 변형이다.
- 공의 실제 위치·속도·HP를 CSS/tween으로 덮어쓰지 않는다.
- 충돌 방향에 맞춰 변형 축을 회전한다.
- HP가 줄었는데 아무 타격 피드백이 없거나, 타격 피드백만 있고 실제 피해·방어가 없는 불일치를 막는다.
- 그림자·무기·소환체는 주인 공의 시각 상태와 일관되게 움직인다.

10.4 히트스톱과 온라인 동기화

기본 구현은 “짧고 제한된 렌더링 타격 정지”로 한다.
- 서버의 60Hz 전투 시뮬레이션을 멈추거나 전체 루프를 sleep하지 않는다.
- 실제 전투 경직은 별도 서버 상태 stunUntil/규칙으로 처리한다.
- 클라이언트는 이벤트의 simTick, 접촉 위치, 스냅샷 버퍼를 사용해 충돌 포즈를 잠깐 강조한다.
- 공 위치·접촉 효과·피해 숫자·표시 HP는 동일 presentationTick의 서버 확정 상태를 사용한다. 최신 authoritative state는 별도로 보관한다.
- 화면 연출이 잠깐 늦춰질 때 HP만 미래 값으로 먼저 0이 되지 않게 한다. 정산 결과가 도착하면 짧은 연출을 마치거나 생략하고 서버 결과로 수렴한다.
- 타격 정지 후 누적 지연이 계속 늘지 않게 재생 시계를 완만히 회복한다.
- 하나의 이벤트 정지 최대 100ms, 반복 정지 누적 예산은 초당 120ms를 초기 상한으로 한다.
- 연타·DoT는 정지를 합치거나 생략한다.
- 이미 오래된 이벤트, 재접속, 숨김 탭 복귀에서는 지난 정지·소리를 몰아서 재생하지 않는다.
- 관전 경기 전환 시 이전 경기 연출 상태를 폐기한다.
- 한 경기의 강타가 다른 14개 경기의 시뮬레이션·화면을 멈추게 하지 않는다.
- 모션 줄임, 소리 끔, 저사양 설정으로 결과·점수·피격 판정이 달라지면 안 된다.

10.5 시각적 타격 효과

필수:
- 공격별 접촉점, 공격 방향에 맞는 스파크.
- 파워에 따라 두께·길이가 변하는 잔상.
- 강타 중 눌림→늘어남→복원.
- 강제 넉백 후 벽 테두리의 순간 강조와 짧은 파편.
- 충전 중 실루엣·발사 방향 예고.
- 가드·패링·흡수·면역의 구분.
- 실제 피해량 기반 숫자; 같은 대상의 짧은 연타는 제한적으로 합산해 숫자 폭주 방지.
- KO 순간 실루엣 강조·공 소멸/파편·승자 확인.
- 공격 범위/장판/중력의 지속시간을 읽을 수 있는 표시.
- 원형 파동 하나를 모든 능력에 색만 바꿔 재사용하지 않는다.

흰 전장 가독성:
- 배경은 흰색 또는 거의 흰색.
- 경계는 선명한 짙은 테두리.
- 밝은 번개·빙결·검기는 유색 코어 또는 어두운 외곽선을 가진다.
- 캐릭터/무기/위험 범위/피해 숫자/이름의 레이어를 명시한다.
- 상시 큰 오라와 파티클로 공을 가리지 않는다.
- 공 이름표가 겹칠 때 가까운 이름표만 최소한으로 조정하고 연결 관계를 유지한다.
- 배경 전체를 반복 점멸시키지 않는다.
- 격렬 / 표준 / 줄임 옵션을 제공한다. 줄임에서도 능력 예고·실제 위치·HP는 남는다.
- prefers-reduced-motion을 첫 설정에 반영한다.

10.6 효과음

- 접촉의 짧은 고음, 충격의 중저음, 발사/비행음, 벽 충돌음을 상황별로 겹친다.
- 금속, 고무, 물, 얼음, 에너지, 마법, 폭발이 구분되어야 한다.
- 검 연타에 망치의 무거운 충격음을 계속 사용하지 않는다.
- 연속 음의 작은 pitch/volume 변화를 허용하되 판정에 영향을 주지 않는다.
- 동시 voice cap, 비슷한 소리 합치기, 공간 방향, master limiter/적절한 볼륨 상한을 둔다.
- 호스트는 현재 선택한 경기의 소리만 듣는다.
- 학생 기본 소리는 꺼 두고 원할 때 켤 수 있게 한다. 호스트도 사용자 동작으로 오디오를 해제한다.
- 음소거·오디오 로딩 실패가 전투를 중단시키지 않는다.
- 브라우저 자동재생 제한을 처리한다.
- Howler를 넣었다는 사실만으로 완료 처리하지 않는다. 실제 음원/합성 패치와 믹싱까지 검증한다.

11. 전장 위 격투게임 HUD
----------------------------------------------------------------------

11.1 1:1 랭킹전과 토너먼트

전장 위 고정 영역에 좌우 두 선수 HUD + 중앙 시간:
- 플레이어 이름.
- 공 이름, T티어, 속성/방향.
- 양쪽 모두 기본 파란색 긴 HP바.
- 현재 HP / 최대 HP 숫자.
- 핵심 능력 한 줄.
- 주요 능력 준비/충전/사용 중/재사용 대기 상태.
- 필요한 상태 이상 아이콘.

공 아래에는 플레이어 이름만 표시한다.
공 근처 상시 HP바·HP숫자·티어·긴 능력 설명은 제거한다.
피해 숫자는 접촉 근처에서 잠깐 나타나도 된다.

11.2 파랑→빨강→빈칸 피해 애니메이션

색 시작값:
현재 HP: #2F80ED
최근 피해: #EF5350
빈 HP: #E7EBF3
텍스트/테두리: #1F2937

HP 100→75 예:
1) 접촉 이벤트가 화면에 표시되는 시점에 파란 구간은 즉시 75까지 줄인다.
2) 75~100 구간에 빨간 피해 잔상이 남는다.
3) 약 200ms 유지한다.
4) 약 450ms 동안 빨간 끝점이 75까지 따라온다.
5) 해당 구간은 최종적으로 빈 배경이 된다.

- 빨간 바 전체를 파란 바 앞에 덮어 HP가 다시 찬 것처럼 만들지 않는다.
- 연타 중 빨간 추종점은 마지막 남은 잔상을 자연스럽게 이어간다.
- 연타가 끝나지 않는다고 빨간 잔상이 영원히 가득 남지 않도록 최대 지연 900ms를 둔다.
- blueHP ≤ trailHP ≤ maxHP 불변식을 지킨다.
- 회복 시 파란 HP 증가와 빨간 잔상을 재조정해 교차/역방향 오류를 막는다.
- 실드가 있으면 HP와 별도 테두리/얇은 표시로 표현하고 HP에 합산하지 않는다.
- 새 경기·새 선수·관전 전환·재접속 때 이전 상대의 빨간 잔상을 재사용하지 않는다.
- HP 숫자는 현재 presentationTick의 서버 확정 값으로 파란 바와 동시에 갱신한다. 빨간 잔상 보간 값으로 숫자를 계산하지 않는다.
- KO 결정과 HP 애니메이션 완료를 서로 대기시키지 않는다.

11.3 능력 가시성

- 능력 아이콘만 놓지 말고 이름과 짧은 상태를 함께 보여 준다.
- 충전·쿨다운은 서버 스냅샷의 실제 값으로 표시한다.
- 프런트엔드 타이머로 임의의 가짜 쿨다운을 만들지 않는다.
- 복잡한 공은 대표 능력 1개와 보조 상태 최대 2개를 상단에 표시하고 상세는 카드에 제공한다.
- 발동 직전/막힘/반격 같은 중요한 상태를 전장 효과와 연결한다.

11.4 럼블 예외

30개의 긴 바를 동시에 전장 위에 쌓지 않는다.
- 호스트가 선택한 집중 관전 공의 긴 HP바.
- 그 공이 최근 교전 중인 상대 또는 호스트가 지정한 상대의 보조 긴 바.
- 생존 수·탈락 로그·선택 가능한 전체 참가 명단은 전장 옆 별도 영역.
- 전체 명단에서 각 공의 HP를 확인할 수 있지만 공 아래 HP바를 다시 만들지 않는다.
- 럼블 학생은 기존 의도대로 전장 없이 자신의 공 상태·누구에게 탈락했는지·등수만 표시한다.

11.5 반응형

- 360px 모바일과 1280px 이상 호스트 화면에서 이름·HP·공 이름이 읽혀야 한다.
- 모바일에서는 두 HUD를 줄여 쌓거나 두 줄로 재배치한다.
- HP와 중요한 버튼을 잘라 내며 전장을 크게 보이게 하지 않는다.
- Top10은 전장을 덮지 않는 별도 영역에 둔다.
- 전체화면은 실제로 동작하는지 확인한다. 실패를 조용히 무시하지 말고 브라우저 지원 상태를 처리한다.

12. 원래 공 그래픽 복원과 외형 다양성
----------------------------------------------------------------------

12.1 세 가지 외형 체계 공존

appearance.kind:
- orb: 기존 금속/발광 코어 중심의 구체.
- portrait: 초상화 중심의 공.
- hybrid: 구체 재질·장갑·코어에 초상화/문양을 결합.

공 정의에 다음을 분리:
combatProfileId, appearanceId, tierFormId, pathId, elementId.
외형은 판정을 바꾸지 않는다. 스킨 차이만으로 새 전투 클래스라고 세지 않는다.

12.2 과거 렌더러 복원

- 과거 skin()의 radial gradient, 장갑 패널, 발광 림, 중심 문양, 고급 오라 링을 재사용한다.
- 과거 level>=20 조건은 현재 최대 level19에서 도달 불가이므로 티어 기준으로 수정한다.
- 오프스크린 렌더 캐시를 유지하되 DPR/크기/외형/티어 변경 시 올바르게 갱신한다.
- 현재 초상화와 신규 무기/오브젝트 렌더링을 삭제하지 않는다.
- 도감·강화 카드·인벤토리·전투에 동일한 외형 정의를 사용한다.
- 이미지 로딩 실패 시 원형 공을 대체 외형으로 표시한다.

12.3 재질과 실루엣

최소 12개 구체 외형 프리셋을 만든다:
금속 코어, 수정, 액체 유리, 용암, 얼음, 전극, 자연 씨앗, 가시 장갑, 사슬/톱니, 궤도 링, 그림자, 프리즘.

단순 원의 색만 바꾸지 않는다.
재질, 내부 코어 움직임, 외부 무기, 윤곽, 발광 방식, 궤적 중 여러 요소가 달라야 한다.
본체 크기와 실제 hitbox의 관계는 읽을 수 있게 유지한다.

13. 애니·만화·영화 원형에서 확장할 공
----------------------------------------------------------------------

13.1 수량과 품질 기준

- 기존 26개 전투 프로필을 유지·개선한다.
- 신규 고유 기믹 24개를 구현 목표로 삼아 총 50개 프로필을 지향한다.
- 작업은 몇 묶음으로 나눠도 최종 완료 보고에서 미구현 후보를 구현된 수에 넣지 않는다.
- 티어 이름·색·초상화만 다른 정의를 고유 기믹에 합산하지 않는다.
- 모든 신규 공은 고유 상태 전이/판정/행동 차이, 예고, 실제 효과, 약점, 상단 HUD 표시를 갖는다.
- 아래 원형은 창작 방향이다. 원작의 공식 능력 재현이나 동일 캐릭터 복제라는 뜻이 아니다.
- 실제 배포 이미지는 자체 제작 또는 사용 범위가 확인된 자산으로 구성한다. 교사가 제공하는 이미지용 스킨 교체 경로는 둘 수 있다.
- 인기 작품의 이름이나 캡처만 붙이고 기존 능력을 그대로 복제하는 방식으로 채우지 않는다.

13.2 신규 기믹 24개 상세 후보

번호 | 작업명 / 참고 원형 | 실제 구현할 행동 | 읽을 수 있는 약점·대응

01 귀환방패 / 캡틴 아메리카 같은 방패 영웅
   방패를 던져 벽 반사 후 귀환시키며, 손을 떠난 동안 방어력이 사라진다.
   투척과 회수 상태를 구분. 무방비 구간에 근접 공격이 유효.

02 진자거미 / 스파이더맨 같은 줄 기동
   벽 고정점에 줄을 걸고 원호 운동 후 줄을 끊으며 관성 돌진.
   직선 순간이동이 아니어야 한다. 고정점과 진행 경로가 미리 보여 장판에 취약.

03 철갑반응로 / 아이언맨·메카 계열
   부채꼴 미사일 살보와 반동 추진. 과열 게이지가 차면 일정 시간 발사·가속이 약해진다.
   지속 화력의 대가로 과열 구간이 명확히 드러남.

04 염력포획 / 우주 염력 기사
   적 탄환 최대 2개를 일정 시간 붙잡아 공전시킨 뒤 방향을 정해 되던진다.
   무한 반사 금지. 근접 공격과 다수 탄환에 취약.

05 시간되감기 / 시간 마법·시간 역행 모험
   자기 자신의 최근 위치로 되돌아가고 최근 피해 일부만 회복.
   전체 경기 시간·상대 HP를 되감지 않는다. 경기당 1회 또는 긴 쿨다운, 회복 상한.

06 연성벽 / 강철의 연금술사 같은 지형 생성
   예고 후 짧은 벽 세그먼트를 생성해 몸체·탄환 반사 경로를 바꾼다.
   벽 수·수명 제한. 공이 갇히거나 생성 즉시 관통 피해를 받지 않게 안전한 배치.

07 변신시계 / 벤 10 같은 제한 변신
   표시된 세 가지 전투 형태를 정해진 순서로 순환한다.
   각 형태는 이동·공격 양상이 실제로 다르고 전환 직후 짧은 빈틈이 있다.

08 축소거인 / 앤트맨 같은 크기 변화
   작은 형태의 회피·속도와 큰 형태의 질량·강타를 교대.
   실제 반지름·질량 변화가 시뮬레이션에 반영. 변화 시 벽 끼임 방지, 큰 형태는 피격 쉬움.

09 잿불불사조 / 불사조·불꽃 부활 계열
   경기당 한 번 치명타를 막고 낮은 HP로 재형성하며 짧은 불꽃 고리를 남긴다.
   부활 횟수 아이콘. 무한 부활 금지, 재형성 후 낮은 체력과 긴 무방비 구간.

10 괴수열선 / 고질라 같은 괴수
   무거운 몸으로 긴 예고 뒤 방향이 천천히 움직이는 열선 부채꼴 공격.
   기존 직선 기공포와 다른 조준/회전 제약. 옆·뒤 공격에 취약.

11 저주매듭 / 저주·표식 계열 만화
   직접 타격으로 표식을 쌓고 다음 조건 충족 시 저장 피해 일부를 지연 전달.
   저장량·대상·시간 제한. 반사/지연 피해가 다시 표식을 무한 증식하지 않음.

12 마법카드 / 카드캡터 같은 카드 마법
   다음 카드가 미리 보이는 고정 순환으로 방어·탄환·구속 중 하나를 발동.
   카드별 판정이 다르며 불리한 카드 구간이 존재. 카드 순서를 숨기지 않음.

13 톱니분쇄 / 전기톱 전사 계열
   톱이 접촉한 동안 피해가 단계적으로 증가하고 과열 시 멈춘다.
   매 tick 무제한 피해 금지. 거리 벌리기·넉백·과열 중 반격으로 대응.

14 표적저격 / 저격수·변형 포격 로봇
   대상 위치를 한 번 추정해 조준선을 표시한 뒤 고속 관통탄 발사.
   명중 시 사거리와 준비시간에 따른 보상을 주되 조준 후 유도하지 않음.
   기존 beam/cannon과 다른 선행 조준·원거리 특화 상태가 필요.

15 광선궤적 / 트론 같은 빛의 이동 흔적
   짧은 구간의 이동 흔적을 남겨 적이 가로지를 때 한 번 피해/감속.
   영구 벽이나 화면 전체 장판 금지. 최대 길이·수명·재적중 간격 명시.

16 흡수모사 / 커비·슬라임 같은 제한 복사
   상대의 허용된 대표 공격 한 종류를 약화된 형태로 잠깐 사용한다.
   복사 가능 능력 목록을 명시. 복사 능력 자체·부활·히든·무한 소환은 복사 불가.
   색만 바뀌는 별 탄환으로 대체하지 말고 실제 선택된 공격이 달라져야 함.

17 축력대검 / 거대한 검을 쓰는 전사
   이동 중 에너지를 모아 무거운 한 번의 넓은 베기를 한다.
   충전 유지와 방출 시점이 보이고 빗나가면 긴 회복. 회전 철퇴와 다른 부채꼴 판정.

18 천둥구름 / 토르 같은 폭풍 영웅
   적의 이전 위치에 구름 표식을 놓고 시간차 낙뢰를 2~3회 내린다.
   각 낙뢰 지점 예고. 현재 위치에 즉시 확정 명중시키지 않음.

19 조류술사 / 물을 다루는 원소 마법
   일정 구간의 흐름으로 공과 탄환 궤적을 휘게 만든다.
   넓은 무조건 피해보다 경로 제어가 핵심. 질량과 진입 방향으로 효과가 달라짐.

20 거울분신 / 분신·환영 닌자 계열
   짧은 수명의 표적 가능한 분신을 만들어 적 공격의 일부를 유도한다.
   기존 잔영 돌진과 달리 분신에 별도 낮은 HP와 표적 규칙이 있음.
   분신은 플레이어/생존자 수로 세지 않으며 범위 공격으로 대응.

21 균사그물 / 숲·덩굴 정령
   최대 3개 씨앗 노드를 연결한 선을 가로지르는 적에게 얽힘을 준다.
   연결선과 실제 판정 일치. 노드 수·수명 제한, 무한 감속 금지.

22 흡혈월식 / 드라큘라 같은 흡혈 계열
   특정 근접 성공 시 실제 준 피해 일부를 회복한다.
   과잉 피해로 회복하지 않고 회복 상한·회당 간격을 둔다.
   장거리 견제·방어로 대응. HP 회복 HUD도 실제로 검증.

23 빙정파쇄 / 겨울 마법·얼음 전사
   냉기 표식을 일정 수 쌓은 뒤 다음 직접타가 표식을 소모해 파쇄 피해를 준다.
   기존 광역 감속과 다른 “축적→소모” 메커니즘. 무한 빙결·파쇄 연쇄 금지.

24 연속격파 / 격투 만화의 연속타·결정타
   제한된 시간 안에 직접 공격을 연속 명중하면 마지막 타가 발사 강타로 바뀐다.
   빗나감/시간 초과로 콤보가 끊김. 평타마다 대형 넉백을 주지 않음.

13.3 기존 능력의 재연출

기존 공도 개선한다:
- 철퇴: 실제 큰 타격점, 한 번의 강제 벽 충돌.
- 삼중검: 세 검의 실루엣·세 번째 타격 차이.
- 탄성주먹: 예비 동작→팔 늘어남→주먹 충격→수축 반동.
- 파동포: 충전 압축→발사→후폭풍.
- 공간접기: 입구/출구 예고와 이동 경로 불연속 처리.
- 그림자 소환: 개별 소환체 상태·공격 방향.
- 중력: 휘는 궤도와 폭발 시점을 구별.
- 아이돌: 박자별 시각 패턴과 세 번째 강한 박자.
- 광전사: 투지 축적, 발동, 끝난 뒤 상태를 읽을 수 있게 한다.

13.4 공별 콘텐츠 계약

각 프로필에 반드시 정의:
id, 이름, 경로/공용 여부, 속성, 등장 티어,
기본 스탯, 발동 조건, 예고, 판정 형태, 쿨다운,
넉백 프로필, 상태이상, 오브젝트 수명/상한,
상성·약점, HUD 상태, 외형 프리셋, 효과음, 테스트 케이스.

도감 문구와 실제 코드의 발동 조건이 같아야 한다.
실험실에서 모든 공을 선택하고 능력 발동까지 볼 수 있어야 한다.
각 신규 능력은 1:1과 30인 럼블 모두에서 안전하게 작동하거나 모드별로 명확한 동일 목적의 수치 제한을 가진다.

14. 상성·성장·밸런스 원칙
----------------------------------------------------------------------

- 높은 티어는 명확한 성장감을 주되 모든 낮은 티어를 자동으로 이기지 않는다.
- 같은 티어에서도 기믹별 유리/불리한 상대가 있어야 한다.
- 불·물·번개·대지·자연의 기존 관계는 유지·정리한다.
- 검술·소환·공간 같은 성장 방향과 원소 속성을 동일한 축으로 혼동하지 않는다.
- 원소 상성 배율은 기본 기존 1.20 / 0.85에서 출발하되 실제 조합 테스트 후 조정한다.
- 히든은 희소한 플레이 스타일이며 전체 상대 우위가 아니다.
- 특정 공의 무적·반사·흡혈·소환이 무한 재귀나 승리 보장을 만들지 않는다.
- 한 종류가 대부분 상대를 이기면 이유를 보고하고 조정한다.
- 티어 차이별 승률, 같은 티어 프로필별 대전 분포, 평균 경기 시간, 선공 편향을 시뮬레이션한다.
- 같은 시드에서 시작 위치를 좌우 교환해 비교한다.
- 평균 승률만 보지 말고 특정 매치업의 극단값도 점검한다.
- 랜덤 매칭 가중치와 능력 밸런스를 함께 조정하되 패배 뒤 몰래 다음 판을 이기게 만들지 않는다.

16.4 전송 범위

- 서버는 모든 경기를 계산한다.
- 학생에게는 자기 경기 스냅샷/이벤트와 공통 랭킹, 자기 지갑/인벤토리를 보낸다.
- 호스트에게는 선택한 경기의 자세한 프레임과 다른 경기의 작은 메타데이터를 보낸다.
- 다른 14개 경기의 상세 좌표를 모든 학생에게 브로드캐스트하지 않는다.
- 호스트의 경기 전환은 권한과 실제 진행 중 matchId를 검증한다.
- Top10은 정산 후 버전 증가와 함께 빠르게 갱신한다. 초기 목표는 정상 연결에서 정산 후 1초 이내.
- 퀴즈 답안·강화 명령마다 전체 학생의 거대한 방 state를 모두 재전송하지 않는다. 개인 ACK/상태와 공개 명단·랭킹 diff를 분리한다.
- 파티클 좌표를 서버 objects에 넣어 전송하지 않는다. 클라이언트가 전투 이벤트로 장식 효과를 생성한다.
- 기존 럼블 개인 summary 캐시가 학생 간 섞이지 않게 유지한다.
- 학생의 질문 정답 키, 복구 토큰, 다른 학생 지갑·개인 원장은 공개 전송하지 않는다.

16.5 재시도·원자성·보안

- 서버에서 소유권·현재 revision·phase·재화·pendingChoice·battleLock을 검사한다.
- 동일 명령 재전송은 같은 결과를 반환한다.
- 강화·채점·큐 참가·대전 정산을 각각 원자적 상태 전이로 처리한다.
- 기존 seen 한도 2048과 rate limit을 긴 루프에 맞게 재검토한다.
- 오래된 command 캐시를 비워도 지급/정산 원장이 없어져 중복 보상이 생기면 안 된다.
- 시간 경계에서 요청 수신·처리 기준을 하나로 정하고 테스트한다.
- 클라이언트가 티어·체력·승점·난수 결과를 조작해서 보내도 채택하지 않는다.
- 운영 배포 전 인증/오리진 설정은 유지한다. 이번 작업에서 운영 비밀값을 읽어 문서에 넣지 않는다.

17. 성능 목표와 실제 검증
----------------------------------------------------------------------

“자동 시뮬레이션이므로 서버 부담이 적다”는 추정만으로 완료하지 않는다.
새 능력과 동시 경기 수가 증가한 조건을 측정한다.

서버:
- 고정 60Hz 시뮬레이션.
- 30학생+호스트 연결, 최대15개 동시1:1, 동시에 퀴즈·강화·랭킹 갱신.
- 전체 tick p95 8ms 이하, p99 16.7ms 이하를 첫 목표로 잡고 환경과 함께 보고.
- 실제 성능이 목표를 못 맞추면 병목·한도 조정·재검증 결과를 남긴다.
- 1:1 스냅샷 15~20Hz 범위에서 측정하고 렌더는 보간.
- 압축을 무작정 켜거나 모든 데이터를 매 frame JSON으로 재생성하는 비용을 점검.

클라이언트:
- 각 기기는 보통 전장 하나만 렌더링.
- 대표 데스크톱에서 60fps 목표, 모바일에서는 최소30fps 수준을 별도 측정.
- 측정 기종·브라우저·해상도·효과 품질·DPR·프레임 시간 기록.
- 서버 tick 숫자를 모바일 렌더 성능의 증거로 쓰지 않는다.
- 파티클, 텍스트 팝업, 오디오 voice, 투사체, 장판, 소환체의 전장별/소유자별 상한을 둔다.
- 15개 전장의 합계 비용도 계산한다. 경기 시작 전 용량을 예약하고 수용 한도를 정한다. 과부하 때 특정 경기의 실제 공격만 임의로 삭제하는 방식으로 성능을 맞추지 않는다.
- 작은 Canvas/오브젝트 풀과 스프라이트 캐시로 할당 폭주를 줄인다.
- 품질 낮춤은 장식부터 줄인다. 핵심 범위 예고·HP·캐릭터를 지우지 않는다.
- 이미지·소리 preload와 실패 대체 경로가 있다.

긴 세션:
- 실제 시간으로 10분 이상 31개 연결을 유지하며 반복 루프 측정.
- 정산·재접속·관전 전환·새 방 반복 후 메모리 증가 추세를 확인.
- 30인 럼블에서는 소환체/장판 많은 조합을 따로 측정.
- 추가 테스트는 성능 위험과 오류를 확인하는 데 사용하며 불필요한 반복으로 구현을 미루지 않는다.
- AWS의 CPU/RAM 여유는 실제 연결 후 확인할 사항이다. 로컬 성능을 AWS 실측이라고 보고하지 않는다.

18. 구현 순서
----------------------------------------------------------------------

단계 A — 전투 한 경기의 완성도
- 구체 외형 복원 + 상단 HP/HUD.
- 약타/강타/발사/벽충돌/가드/KO 프로필.
- 실제 넉백과 시각 연출 분리.
- 대표 4~6개 공으로 체감 시연.

단계 B — 수업 루프의 완성
- 학생별 퀴즈·지갑·3슬롯·새 강화 규칙.
- 성공 메시지 뒤 선택.
- 랭킹 큐·자동 경기·승점·Top10·다시 도전.
- 호스트1+학생2 이상 실제 소켓 검증.

단계 C — 콘텐츠 확장
- 신규24개 프로필을 여러 묶음으로 구현.
- 12개 이상 구체 재질 프리셋과 portrait/hybrid 공존.
- 각 공의 예고·피격감·약점·도감·실험실 완성.

단계 D — 규모와 회귀 검증
- 30인/15경기, 장시간 루프, 모바일, 기존 토너먼트/럼블.
- 경제·매칭·능력 조정과 최종 시연.
- 운영 배포용 변경은 별도 검토 가능한 상태로 준비.

단계 A 또는 B만 끝내고 전체 v2가 완료됐다고 보고하지 않는다.
진행 보고는 구현된 기능과 실제 남은 항목을 구분한다.

부록 A. 강화 경제를 이 값으로 시작하는 이유
----------------------------------------------------------------------

이번 명세의 확률과 실패 규칙을 Fraction 유한상태 전이로 계산했다.
일부 시행을 뽑은 Monte Carlo가 아니라 유한 예산의 전체 상태 확률을 합산한 결과다.
모든 계산 정책에서 최종 확률 합이 정확히1인지 검증했다.

가정:
- T20 공1개, 시작 유지권0개.
- 총 예산=10+정답수×2.
- 강화1장, 유지권2장.
- T10 전에는 무보호.
- 보호 정책은 T10부터 항상 유지권을 사용하고, 없을 때 구매2장+시도1장 총3장이 없으면 중단.
- 성공하면 유지권을 보존하고 실패 시 소비.
- T1 도달 시 중단.
- 시간, 다른 슬롯, 거래, 복제, 천장, 추가 보상은 포함하지 않음.
- “도달”은 그 티어 이상을 한 번이라도 얻은 이력. 자동 복원/보장값이 아님.

보호 정책:
총30장 / 정답10개: T5 이상52.3802%, T1 0.1794%, 평균최종T5.4266.
총50장 / 정답20개: T5 이상96.6456%, T1 6.2560%, 평균최종T3.3367.
총70장 / 정답30개: T5 이상99.8598%, T1 25.8440%, 평균최종T2.2920.

무보호로 끝까지 시도:
총30장: T5 이상8.5790%, T1 0.006668%, 평균최종T14.0024.
총50장: T5 이상16.8861%, T1 0.015528%, 평균최종T14.1486.
총70장: T5 이상23.8354%, T1 0.024166%, 평균최종T13.8593.

초기10장만 사용:
T10 도달33.8026%, 평균최종T11.7690.

현재와 같은 상위 성공률에서 T10→T1을 무보호로 연속 성공할 확률:
0.8×0.7×0.6×0.5×0.4×0.3×0.22×0.15×0.1
= 0.000066528
= 0.0066528%.

강화권을 계속 공급하면서 T10부터 보호하는 경우 평균 필요량:
T10: 약12.78장.
T5: 약31.31장.
T3: 약50.95장.
T1: 약96.95장.

의미:
- 초기화 페널티만 추가하면 운이 나쁜 학생의 최종 공은 계속 약해질 수 있다.
- 3슬롯 보관·유지권·패배 시 공 보존을 하나의 설계로 구현해야 한다.
- T1은 모두의 필수 종착점이 아니다. T5~T10에서도 대전과 상성 선택을 즐길 수 있어야 한다.
- 이 결과는 학급에서의 실제 정답속도·선택속도·경기관전을 포함한 결과가 아니다.
- 실제 데이터로 “첫 T10 시간”, “보관 공 확보율”, “패배 후 재도전율”, “초기화 후 복귀시간”, “매칭 대기시간”을 확인한 뒤 조정한다.

재현할 상태 전이:
state=(사용한티켓, 현재level, 최고level, 보유유지권여부).
성공→level+1, 최고level갱신, 티켓1소모.
무보호실패→현재level<10이면max(0,level-1), 아니면0.
보호실패→level유지, 유지권소비, 티켓1소모.
유지권구매→티켓2소모, 보유유지권true.
총예산소진·보호정책구매불가·T1에서종료상태로모으고합1검증.

----------------------------------------------------------------------

1) 현 저장소/브랜치/지침을 읽고 현재 코드와 위 조사 기준의 차이를 기록한다.
